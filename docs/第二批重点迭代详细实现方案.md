## 3. 底层框架与通用约束

### 3.1 只读采集与后台任务

新增受限的本地读取任务，共用于诊断、空间盘点、恢复预览和冲突扫描。建议落在 `src/main/read-jobs.ts`，避免四个模块各自复制进度、取消和过期逻辑。

- 任务固定 `gameId`、已保存的根目录、数据目录、创建时间和输入摘要；切换游戏不使旧任务改用另一个游戏的路径。
- 创建时通过现有主进程队列取得上下文；长时间只读工作在后台分步运行，进度／取消接口保持响应。文件恢复、清理提交、保护设置仍进入共享写队列。
- 读取期间发现设置、库内容修订、相关 INI 或副本改变时，结果标记过期；不要声称所有检查来自同一原子时刻。执行恢复／清理还须重新校验。
- 初始预算：同一窗口最多两个只读任务，同类同游戏只运行一个，目录遍历并发最多四项。重复点击复用正在运行的任务或明确提示等待，不堆积扫描。
- 默认只读本地内容，不自动测试网站连接、不上传报告，不运行游戏、未知 exe 或 DLL。检查失败按子项返回，其他检查可继续。
- 预算上限应集中配置：深度、文件数量、读取字节、输出字节和任务时限。初始大目录盘点最多 200,000 个节点／32 层；达到上限显示“结果不完整”，不以部分总量生成删除确认。
- 取消只读任务不写业务文件；选择“返回”或离开页面不得隐式执行恢复或清理。取消后的过期结果不得用于提交。
- 只读任务使用页内进度状态，不用全局 onBusy 锁住整款管理器的导航。离开时只取消／隐藏当前读取，旧游戏响应不能覆盖新页面；真正提交文件期间才使用现有写入忙状态。

拟任务结构：`ReadJob {id, kind, gameId, stage, progress, observedAt, stale, warnings, result?}`。结果在内存中短期保留，建议完成后十分钟失效、缓存最多二十项；重新启动后重新采集。任务 id、计划 token 和结果 id 各自有清楚用途，不能跨模块通用。

### 3.2 统一状态与可信依据

诊断事实建议采用 `pass / warning / error / unknown / skipped`，同时记录固定检查键、检查时间、简短原因及依据引用。颜色之外有文本状态。

`unknown` 用于权限失败、未知版本、无法判定的规则与不支持的表达式；不映射成“正常”或“未安装”。人工兼容性标记、网站摘要验证、目录启用、loader 读取范围以及游戏内效果分别展示。

实现共用的 `InspectionContext` 和 `FileEvidence`：路径在主进程规范化；文件证据包含身份、大小、时间及必要的 digest。允许 UI 返回 Mod ID、相对路径和报告键，禁止 renderer 传任意绝对路径要求读取／删除。引用解析始终验证当前所属游戏、根目录、普通文件及无链接边界。

### 3.3 数据与兼容

| 数据 | 设计 |
| --- | --- |
| 现有库／设置／预设／恢复记录 | 保持版本 1 的读取与未知字段保护，不借本批批量重写旧库 |
| `recovery-preferences-<game>.json` | 新版本化 sidecar，按恢复 ID 保存保护标记；不修改恢复包的原记录，不因为解除手动保护取消系统保护 |
| `recovery-cleanup/<jobId>/manifest.json` | 独立、受限的清理提交记录，记录固定目标、阶段、身份及逐项结果；供失败重试和重启展示 |
| 新备份内容清单 | 可选的版本化清单，记录复制完成后实际文件范围和大小；字段注明是路径／大小验证还是内容摘要验证。旧包没有清单时显示已知检查范围，不能伪装成摘要完整性已验证 |
| 本地排序偏好 | 建议 renderer 的版本化 `localStorage`，按游戏保存条件数组；复用现有本地主题／侧栏偏好的处理方式，无需为显示顺序新增文件操作 IPC |
| 诊断结果、冲突上下文、恢复计划 | 内存缓存和过期 token，不持久化敏感原文或长期有效的操作计划 |

sidecar 写入使用现有原子写。非法保护文件应保留原文并禁用清理，不能当成“所有副本未保护”。无效排序偏好可回退到名称升序，因为它只影响显示。

## 4. F03：环境诊断与诊断报告导出

### 4.1 检查范围

| 检查组 | 采集内容 | 判断边界 |
| --- | --- | --- |
| 当前上下文 | 管理器版本、运行平台／架构、当前游戏、已保存路径、检查时间 | 不读取未提交的设置草稿；不导出账户名或机器名 |
| 路径 | 游戏／XXMI／Mod 目录是否存在、是否普通目录、是否可读取、目录重叠及可用空间读取结果 | 权限失败为未知；默认不创建测试文件，不以只读检查证明可写 |
| Launcher／Importer | exe、importer 目录、d3dx.ini；配置实际指向的 importer 与所选游戏 | 文件存在不等于进程已启动；异常或外部 importer 路径明确展示 |
| 组件记录版本 | Launcher、XXMI、当前 ZZMI/EFMI Manifest 值、来源及解析状态 | 显示“安装记录版本”；不把 Manifest 值当成 DLL 运行时版本或签名验证结果 |
| VC x64 运行库 | 固定注册表位置的只读查询 | 确认不存在与查询失败分开；不自动下载安装 |
| loader 读取规则 | 递归 Include 范围、排除规则的所属节及行；管理根是否在已确认读取范围 | 支持明确的静态规则；动态／重复歧义／自定义扩展为未知，不运行 loader 表达式 |
| 实际 Mod 状态 | 总数、实际启用、自身停用、父目录停用、人工兼容性标记及已有互斥异常 | 只统计读取范围内可识别项；目录启用不能证明游戏生效 |
| 依赖与配置 | 启用成员的缺失／最低版本问题、活动配置脏状态、内容修订不符 | 复用第一批规则；诊断只展示，不联动、不生成可执行启停授权 |
| 待处理操作 | 中断提交、已提交待清理、清理中断、所涉及的根 | 在根目录暂时不存在时也能检查记录，不依赖先成功调用 ModService.context |
| 操作摘要 | 最近相关失败类别、操作／副本 ID 和时间 | 不展示 Cookie、来源查询参数、INI 文本和原始错误堆栈 |

组件读取建议抽为 `src/main/installed-versions.ts`：新函数返回 `known / missing / unreadable / invalid` 和证据；现有依赖模块继续取得原来的三个版本值。两个入口的最低版本判断必须一致。

诊断需要新增只读库采集路径：旧库迁移、封面索引发现、根历史归档只发生在既有管理流程。损坏库或中断根不妨碍诊断其他项；此时数量与依赖检查显示跳过／未知原因。

### 4.2 报告与隐私

导出流程为：完成检查 → 预览脱敏报告 → 选择是否包含 Mod 名称／相对文件名 → 原生选择保存位置 → 写入固定格式的本地报告。默认提供 Markdown，另提供版本化 JSON；两份可分别导出，不强制 ZIP 打包。

- 默认绝对路径替换为 `${XXMI_ROOT}`、`${MOD_ROOT}`、`${GAME_ROOT}`、`${DATA_ROOT}`。替换按规范化路径组件进行，不能只替换用户名字符串；根外路径只显示角色、风险和脱敏标识。
- 默认使用报告内短 ID 代替自定义名称，不附配置全文、完整目录树、账号、Cookie、Token、站点下载地址及可能含私密参数的 URL。
- 日志摘要重新序列化白名单字段，最多最近 100 条／256 KiB。不能因为现有日志已经排除正文就无条件打包整个日志目录。
- 默认报告最大 2 MiB；截断处明确计数。不输出原始异常对象或堆栈，采用固定检查键和可解释的错误类别。
- 名称或 INI 片段不作为 HTML 执行；Markdown 特殊字符、代码围栏和控制字符妥善处理，报告预览使用现有安全文本展示方式。
- 两份格式复用同一个已脱敏模型，导出时再次显示游戏／检查时间／过期状态；未完成或过期诊断可导出为“部分／过期结果”，不能标全通过。

导出通过原生保存对话框取得目的地；允许用户明确覆盖所选报告文件，拒绝把报告写到管理器设置、库、预设、恢复记录或已管理 Mod/loader INI 等受保护业务文件。先写同目录临时文件，再原子提交；取消或写入失败不截断已有文件。

### 4.3 页面与可交付条件

设置页增加“诊断”页签，保留“常规设置”和“关于”。页签切换保持所有路径／更新源草稿；键盘的左右、Home/End 和焦点管理改成三个页签的通用规则。

顶部显示当前游戏、已保存路径的简要角色及采集时间，提供“开始检查／重新检查、取消、预览报告、导出”。正文按检查组展开，问题有“查看依据”和明确导航入口：路径问题转常规设置，中断问题转恢复页，依赖／配置问题转对应 Mod／预设。导航不自动同步配置或提交修复。

完成条件：结果在路径缺失、库损坏、未知版本和中断状态下仍可用；脱敏导出可核对，检查未写入业务文件；两游戏结果无串用，草稿保持。

## 5. F04：备份空间管理与恢复预览

### 5.1 空间盘点与保护

空间概览分别统计：完整快照、Mod 换包／移除副本、INI 副本、历史配置修订、文件操作暂存、清理暂存，以及无法识别的内容。按游戏与副本原根展示，避免把某个游戏当前 Mod 目录算入可清理空间。

显示逻辑字节数、文件数、最后盘点时间与检查范围。权限失败／链接／数量超限显示未知或部分统计；不可清理项也显示占用原因。Windows 压缩、稀疏文件或硬链接可能让逻辑大小不同于实际释放空间，UI 不能承诺清理后腾出相同字节数；不确定时提示无法精确估计。

保护分两类：

1. 用户保护：可以保护／解除保护完整、可识别副本，按恢复 ID 持久化。
2. 系统保护：正在创建、恢复、清理或被未完成操作依赖的对象，及无法确认归属／完整性的对象。系统保护不能由解除手动保护绕过。

首次可永久清理范围为已完成、可识别的 `snapshot / mod-delete / mod-replace / ini` 副本，必须有当前数据目录内匹配的 UUID payload 和记录。旧 `legacy`、损坏索引、`.partial-*`、v1/v2 中断记录、已回退人工副本仅展示和提供受限位置查看；处理中断／完成暂存继续走原恢复服务。

独立配置修订只做空间及引用展示，首次不做修订垃圾回收。引用必须考虑活动配置、各预设、换包副本的 profileContext、完整快照、旧根归档和未完成操作；不能以“当前页面未选中”判断未引用。将来清理修订另行明确范围，不能在删除一个普通副本时顺带删掉共享配置。

旧根副本可以盘点与明确选择清理，它们的恢复仍遵守原根匹配规则。清理某个已移除 Mod 的唯一副本要提示失去该副本的恢复能力；库中的删除标记继续保持，不因清理副本使 Mod 重新变成有效记录。

### 5.2 恢复预览必须与实际行为一致

建立 `RestorePlanner`，由预览和 BusinessService 的实际恢复共同调用同一范围解析。不能只在前端根据名称列几项，然后继续运行另一份独立恢复逻辑。

| 类型 | 预览范围 |
| --- | --- |
| INI | Mod 当前身份与位置、具体文件、现有／备份摘要、编码、变化行概览和恢复前副本；不改变收藏／标签等信息 |
| 单 Mod | 当前同 ID 路径、原保存路径、被移出的改名后别名、文件增加／替换／移出范围、绑定／版本／内容修订、启停与配置关联；当前收藏／标签保持规则 |
| 完整快照 | 当前游戏整个 Mods 根、角色封面、Profiles、库／预设及该游戏路径；快照后新增 Mod/文件从当前根移出并进入恢复前副本；其他游戏和桌面偏好保持 |
| 旧快照 | 无 Profiles 或角色封面时的确切恢复行为、会清除的无效活动关联；异常配置引用需要处理，不能假称保留了不存在的副本 |
| 中断记录 | 回退／已提交暂存清理的真实范围、新内容人工副本、可能阻止回退的外部变化；不归到普通备份删除 |

完整快照目前是整目录提交。内容相同的文件也属于被重建的目录范围，不能标成“此文件未被操作”。界面同时列内容差异和提交范围；不在本批悄悄改成增量恢复算法。

预览包括：固定的游戏与根、源副本状态、受影响的 Mod ID、路径变化、元数据／配置／设置变化、将创建的恢复前副本、依赖与互斥阻断，以及各目标卷的空间估算。空间估算注明复制／暂存开销和未知项，不把根外已存在文件默认为无关。

差异分级采集：先给准确的目录级覆盖范围和文件清单，再按需计算摘要及有限文本差异。仅尺寸／时间相同不能标“内容相同”；未算摘要的显示“尚未比较”。统计未完成或预算超限时，允许查看摘要，不能生成省略关键影响的执行确认。

恢复 token 绑定副本身份／记录摘要、原根、目标内容证据、库与预设修订、相关 INI 摘要、保护和操作状态以及依赖上下文。建议有效期两分钟。提交时重新核对这些事实、空间及依赖；发生外部编辑／改名／根变化时停止并要求重新预览。不能靠 contentRevision 替代外部 INI 变化检查。

依赖阻断仍先解决；未知版本及联动停用由用户明确接受。先保留恢复前完整副本，再交现有队列提交。保护标记禁止清理副本，不禁止明确恢复该副本。

### 5.3 手动清理与失败恢复

清理流程为：多选可清理项 → 查看每项名称／类型／原根／逻辑大小与失去的恢复能力 → 检查保护、引用和任务状态 → 预览确认 → 原生明确“永久清理所选副本” → 逐项提交并报告。

- 新增 `RecoveryCleanupService`，固定只操作当前 `userData/removed/<game>/<uuid>` 及匹配记录，renderer 只传 ID。计划返回展示信息，客户端不提交删除路径。
- 清理 token 绑定 ID 集合、payload／记录身份、大小证据、保护索引修订和相关任务状态。执行进入共享写队列，逐项重新检查；用户保护或业务引用在确认后变化时，停止受影响项，不绕过保护。
- 初始最多一百个副本／次；完整空间盘点后才能预览所选项总量。只读取消不改变文件；删除开始后取消在下一个完整副本边界生效，不承诺恢复已永久删除内容。
- 第一个移动前持久化归属和阶段记录。先把 payload 与记录移到同一数据卷内的管理器专用清理暂存，核对归属，再永久删除；暂存移动本身不算空间释放。
- 始终验证解析后的绝对目标在固定允许目录内，检查祖先及子项 reparse/link 边界、文件身份；拒绝磁盘根、数据根、Mod 根、设置和跨游戏路径。FS 操作不拼 shell 命令，不跟随链接。
- 移动只完成一半、文件占用、权限失败或中途退出时，记录准确阶段，列表展示“待处理清理”。重启不自动恢复永久删除；需用户选择继续清理或撤销尚未删除的完整项。
- 已删除一部分的副本不能重新发布为可恢复的完整副本。未删除完整项撤销时，原位置被占用则停止，不覆盖；部分项保留剩余内容和记录供核对，显示恢复能力已失效。
- 未完成清理与其对象互相锁定，不能同时恢复／再清理。不能依靠会滚动丢失的操作日志判断依赖；归属和依赖必须由持久记录／现存引用核对。记录不支持可靠判断时保守禁止清理，并说明原因。
- 管理器更新安装要等待清理提交及文件提交收尾；进度和取消保持可响应。成功、跳过、失败、取消逐项报告，日志记录 ID、结果、清理任务关联和估算字节，不记录原文或绝对路径。

新增清理记录是专用的文件恢复边界，不扩大现有 FileOperations 的 Mod 文件路径白名单，不搭建任意文件系统事务接口。

### 5.4 页面与可交付条件

备份与恢复页顶部显示空间概览及盘点时间；列表增加类型／原根／大小／用户保护／系统保护／可恢复状态。支持保护筛选、时间／类型／大小排列、多选和“预览清理”；保护项默认不能勾选，原因可查看。

选择备份后提供“预览恢复”，展开提交范围与差异，再确认恢复；原恢复按钮不得绕过新预览。中断恢复和清理中断展示各自专用操作。历史副本或未知项有受限位置查看入口，但不附带可任意读取或删除的路径接口。

完成条件：所选范围、实际文件、结果及空间显示一致；未选择项和其他游戏保留；所有保护与过期情况生效；恢复范围和第一批个人字段／配置引用规则一致；清理失败和强退之后无完整性误标。

## 6. F07：冲突详情与辅助处理

### 6.1 上下文采集与判断口径

以当前实际启用 Mod 的 INI 为扫描范围，沿用停用祖先／停用文件／无链接和编码约束。新上下文解析器建议独立为 `src/main/ini-context.ts`，保留原文行号和 digest，不把 INI 简化成会丢重复键的对象。

每个候选发生位置包括：`modId`、内容修订、Mod 内相对文件名、根相对展示路径、文件 digest、节名／类型、hash 行、有限片段、显式 namespace、condition/if 等条件原文、match/filter 字段、局部资源及 run 引用、解析警告。

Mod 内路径与根相对路径必须区分。当前 HashLocation.relativePath 是根相对展示值，不能直接传给 readIni。通过稳定 ID 解析当前目录后，只允许经校验的 Mod 内文件。

候选主要按类型与规范化 hash 分组，界面保留跨类型相同文本的上下文说明，旧 conflicts 接口保持兼容。不同 namespace、相同资源引用、条件不同、match/filter 值不同都作为依据展示，不自动升级为“确定冲突”或“确定不冲突”。

本批明确不求值动态条件、不推演 draw call、不展开不受限的递归 run/include、不从相同 hash 推断载入优先级。跨文件／跨 Mod 的未解析引用标未知；对文件系统资源只展示可验证的存在／缺失状态，遇到根外路径或链接不跟随。

输出示例为：“两款实际启用 Mod 含相同类型 hash；两处条件文本不同，是否同时生效未知。”问题解释可合并第一批依赖／互斥状态，但这些手动声明不替代渲染证据。

### 6.2 有界读取和安全定位

- 原 INI 每文件 4 MiB 上限保持，UTF-8／BOM／UTF-16及行号规则复用现有服务。异常编码按文件报告，不使整个报告变成空结果。
- 新扫描初始总读取预算 128 MiB、10,000 个 INI；最多回传 2,000 个候选组，超限显示不完整。总读取和候选输出分别限制，取消按文件边界生效。
- 扫描返回有限摘要，单组详情按需读取，初始片段每处最多前后各十行、单组最多 64 KiB、递归引用深度为零。大量发生位置分页，不能把全部 INI 文本塞入首次 IPC 返回。
- 结果绑定游戏、已保存根、Mod ID／内容修订、文件 digest。进入详情或点击定位时重读；文件变更时提示刷新，不对旧行号执行编辑。
- 文件改名但内容与身份有效时按稳定 ID 定位当前文件；文件缺失、根改变、替换内容或跨游戏引用时拒绝旧定位。
- INI 编辑器新增受限的 `relativePath + line + expectedDigest` 打开目标；新打开／切换目标经过现有草稿放弃确认，自动滚到对应行只作为定位，不能自动修改文本。

### 6.3 辅助操作

允许从详情查看 Mod、打开指定 INI、明确选择停用某些 Mod、或用选定 Mod 创建／编辑手动互斥组。停用使用已有 batch/operate 和依赖确认，互斥使用已有组接口；候选窗口不新增绕过依赖的“强制停用”方法。

操作前列出受影响成员与必要联动，冲突候选本身不决定应该关闭谁。完成后刷新主窗／浮窗和当前候选；失败显示真实逐项结果。已停用的项不再列为实际启用重叠，用户取消时不改目录。

页面沿用“候选冲突”，增加 hash／Mod／角色／类型筛选、组摘要及详情。条件、引用、解析警告均作为可展开依据；“定位原文件”优先使用内置编辑器，受限“在资源管理器中显示”可按 ID 请求主进程定位，不接收绝对路径。

完成条件：摘要、详情和定位指向同一批实际文件；未知语义不会被误判；辅助操作与第一批规则一致，旧编码／草稿／稳定身份及虚拟列表行为保持。

## 7. F11：多条件排序

### 7.1 排序语义

| 字段 | 比较方式与未知处理 |
| --- | --- |
| 名称 | 沿用当前中文 locale 比较；默认名称升序，不在本批悄悄改变默认数字排序规则 |
| 导入时间 | 有效 importedAt 按时间比较；空／无效为未知，升降序均把未知放在末尾 |
| 启停状态 | 明确顺序为启用、自身停用、父目录停用；两种停用同时存在时按页面当前父目录停用状态显示 |
| 收藏 | 布尔排序，可选收藏优先；不与“只看收藏”筛选混淆 |
| 角色 | 当前 metadata.character；空值排末尾，显示值不变 |
| 分类 | 当前 metadata.category；空值排末尾，显示值不变 |

最多三个不重复字段；支持每项升降序、上移／下移、删除和重置。所有选定字段相同后，按名称、规范化相对路径、稳定 ID 兜底，确保同一组数据重启／重扫后次序稳定。

本批不提供版本字符串、文件占用或未记录修改时间的排序：版本有自定义文本，后两项需要额外磁盘采集，避免列表操作隐式触发全库读取。后续需要这些字段时再确定数据依据。

排序仅改变显示顺序，不移动目录，不写 loader 配置，不定义游戏载入顺序。范围先覆盖主窗 Mod 列表；角色概览、配置成员、恢复列表和冲突列表各有自己的顺序，不随 Mod 排序偏好改变。

### 7.2 状态和性能

- 搜索与现有分类／角色／启停／收藏／多标签筛选先完成，再对结果副本排序；不原地 sort library.mods，不影响原始库及预设数据。
- 选择和详情始终按 Mod ID；排序不取消离屏多选，也不让详情变成“当前行号”的另一项。被筛掉的已选 ID 保持，操作仍基于选择集合。
- 作者、标签、版本及依赖草稿保持；只有用户切换身份／游戏／根或明确放弃时才按现有规则处理。排序偏好不是 metadata/provenance 保存事件。
- 各游戏保存一份条件，切换角色继续使用该游戏偏好；根改变时无需迁移 ID，因为偏好不包含 Mod 身份和路径。损坏本地偏好回退默认值，不影响业务配置。
- 源数据更新时重建时间／字符串比较键；筛选或排序条件变化复用索引和 Intl.Collator，在 useMemo 内执行，不进行 IPC、文件扫描或封面重读。
- VirtualList 增加可选的滚动锚点策略，默认保持原行为；Mod 列表排序时优先保留首个可见 Mod ID 与相对偏移，锚点失效时按明确规则回退。新选择可以滚到详情，单纯排序不反复强制居中。
- 保留大库虚拟化阈值、有界建议和稳定行高。排序编辑支持按钮／键盘操作，不要求拖拽。

完成条件：组合主次和未知位置正确、重复结果稳定、重启偏好保持；多选／详情／草稿无丢失，排序不写库或改变真实启停。

## 8. 拟接口与页面连接

命名用于约定模块边界，开发时以实际 contracts、typed preload、IPCContracts、handler 和 AST 清单统一落地，不提前宣称新增数量。服务内部 helper 不必暴露成 IPC。

| 拟方法 | 返回与用途 | 写入／确认 |
| --- | --- | --- |
| `startDiagnostics(game)` | 创建只读诊断任务，返回 jobId | 只读 |
| `readInspectionJob(id)`、`cancelInspectionJob(id)` | 通用只读任务进度、结果／取消；校验任务归属 | 不写业务文件 |
| `previewDiagnosticExport(id, options)` | 返回已脱敏 Markdown／JSON 模型及范围摘要 | 只读 |
| `exportDiagnosticReport(id, format, options)` | 原生保存对话框，取消返回 null，报告写入结果 | 仅写明确选择的报告 |
| `startRecoveryInventory(game)` | 空间和保护／状态采集 | 只读 |
| `setRecoveryProtection(game, ids, protected)` | 返回更新后的保护状态／逐项结果 | 共享写队列；解除不绕过系统保护 |
| `prepareRecoveryRestore(game, id)` | RestorePlan：影响范围、差异、依赖／空间及 token | 只读 |
| `applyRecoveryRestore(game, token, choices?)` | 原生范围确认后执行，返回 LibrarySnapshot 或取消 | 原队列、原副本／依赖规则 |
| `prepareRecoveryCleanup(game, ids)` | CleanupPlan：确切副本集合、占用、禁止原因及 token | 只读 |
| `applyRecoveryCleanup(game, token)` | 原生永久清理确认，返回逐项结果与清理 jobId | 独立清理记录＋共享写队列 |
| `manageRecoveryCleanup(game, jobId, action)` | 继续清理／撤销仍完整未删除项／读取结果 | 需明确操作；不自动重试永久删除 |
| `startConflictInspection(game)` | 实际启用 INI 候选任务 | 只读 |
| `conflictDetails(game, resultId, groupId)` | 按需有限上下文、定位令牌和解析警告 | 只读，不传 hash 任意搜索整机 |
| `revealManagedLocation(game, reference)` | 校验 Mod／副本 ID 后显示所属文件位置 | 主进程固定归属解析，无任意路径参数 |

F11 用共享纯函数和本地偏好 hook，不新增排序 IPC。INI 定位优先采用 App 到 IniEditor 的直接组件调用，补齐目标 DTO 和草稿确认；精确内容读取继续用已有 readIni。

现有 `recovery`、`restore`、`conflicts` 保留兼容。新 UI 恢复入口统一走 prepare/apply；旧 restore 也需通过同一个 Planner 和原生范围确认，不能成为绕过预览／过期校验的入口。旧消费者若迁移，AST 语义标明 compatibility-only，而不是伪造使用点。

现有 Result.details 当前是 DependencyPlan；新增恢复／清理错误不要直接塞入错误类型。可保持旧 details 并增加可选 discriminated context，或给新方法定义独立成功 DTO／明确错误码，编码时择简单兼容做法并用旧调用测试验证。

拟页面连接：

| 页面 | 连接内容 |
| --- | --- |
| 设置／诊断 | start/read/cancel → 分组结果 → 脱敏预览 → 导出；三页签草稿保持 |
| 备份与恢复 | inventory → 大小／保护 → restore 或 cleanup plan → 明确确认 → 真正提交 → 逐项结果／中断处理 |
| 候选冲突 | scan → 组摘要 → 按需详情 → 内置 INI 定位或既有批量／互斥操作 → 重扫 |
| Mod 列表 | 本地偏好 → 已有筛选结果 → 纯排序 → 有界行与稳定 ID 选择 |
| 主窗／浮窗 | 写操作成功广播现有 desktop:changed；纯显示排序和只读报告不广播文件变更 |

所有新接口仍仅可信本地窗口可调用，远程网页没有访问权限。长任务状态接口加入现有响应通道策略；文件提交不得嵌套等待同一写队列而造成死锁。

报告导出、备份保护、恢复计划执行和永久清理限定可信主窗口发起；浮窗继续使用既有启停及必要确认。服务层同样验证 ID／游戏／归属，不把权限判断只放在按钮可见性上。

## 12. 外部依据与实施时核对

本次核对使用官方源码与项目资料。原始 3Dmigoto 的[配置处理源码](https://github.com/bo3b/3Dmigoto/blob/master/DirectX11/IniHandler.cpp)含 namespace 与条件解析，而 [XXMI 官方项目](https://github.com/SpectrumQT/XXMI-Libs-Package)采用定制分支；这些依据说明为什么上下文需要保留、规则适配需要核对。将上游规则直接当作当前用户所装 DLL 的完整行为是不成立的。本方案据此选择只读线索和未知语义，不承诺自动证明渲染冲突。

- [3Dmigoto 配置处理源码](https://github.com/bo3b/3Dmigoto/blob/master/DirectX11/IniHandler.cpp)：核对前导 namespace／condition 与节处理方式；作为解析边界依据。
- [3Dmigoto 官方配置样例](https://github.com/bo3b/3Dmigoto/blob/master/Dependencies/d3dx.ini)：核对 override、匹配和过滤字段；不在本批实现完整命令求值。
- [XXMI 定制库官方项目](https://github.com/SpectrumQT/XXMI-Libs-Package)：核对与上游的分支关系及扩展入口，编码时针对支持的版本留脱敏样本和规则证据。
