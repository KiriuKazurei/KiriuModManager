# 接口调整说明

更新日期：2026-10-13。当前接口为 40 个异步调用及 1 个事件订阅。本文件记录已实现语义及 Cursor 接入要求；功能代理不修改 `src/renderer`，页面状态、反馈与布局由 Cursor / GUI Agent 负责。

当前全面 API 与调用规则的权威入口为[桌面接口文档](桌面接口文档.md)。本文仍用于本轮变更对照、Cursor 迁移示例与验收，不标为废止。

## P2：兼容调整，签名未变

P2 完成时 `DesktopAPI` 为 38 个异步调用及 1 个事件订阅；P2 没有签名变更。P4 兼容新增两项后当前为 40 个异步调用及 1 个事件订阅，完整实际清单见 `docs/desktop-api-inventory.json`。调用继续走 `window.kmm` → preload → 主进程受信任 IPC → 服务；类型定义在 `src/shared/contracts.ts`。接口数量由源代码核验，不用固定计数限制扩展。

| 接口 | 旧/新签名（相同） | 已实现语义调整 |
| --- | --- | --- |
| `scanMods` | `(game: GameId) => Promise<Result<LibrarySnapshot>>` | 只对新记录使用库中注册分类推断。已知分类单层路径只填分类；分类/角色两层允许空外观；未知短路径保留直接角色/外观解释；三层及深路径沿用原规则。既有 metadata 不重推断 |
| `importMods` | `(game: GameId, kind: 'folder' \| 'archive') => Promise<Result<ImportResult>>` | 新导入记录采用同样推断规则；已有文件不覆盖。取消、部分成功结构未变 |
| `operateMod` | `(game: GameId, id: string, operation: ModOperation) => Promise<Result<LibrarySnapshot>>` | 仅大小写变化的 rename 现在实际修改物理目录名，返回真实名称；稳定 ID、metadata、停用状态保持。同名目标先返回明确拒绝覆盖错误，原目标内容不变 |

`GameId = 'zzz' | 'endfield'`。`ModOperation` 为 `toggle {enabled:boolean}`、`rename {name:string}`、`metadata {metadata:ModMetadata}` 或 `classify {category:string,character:string,appearance:string}`，由 `kind` 区分。`ModMetadata` 含 category、character、appearance、author、description。metadata 保存不移动文件；classify 才移动，空 appearance 合法。记录 ID 必须属于参数指定游戏及其当前已保存库根。

所有异步返回 `Result<T> = {ok:true,value:T} | {ok:false,error:string}`。错误不代表已经成功；页面保留待编辑数据并展示 error。文件夹/归档导入返回 `{library, importedIds, errors, canceled}`：成功与错误可以同时存在，分别呈现，不将部分成功简化为全部成功或失败。原生导入取消为 `canceled:true`；图片选择、替换、移除确认取消的成功 Result 中 `value:null`，不修改相关文件或图片引用。生产接口不接收任意导入/删除绝对路径；选择来源和确认由主进程原生对话框完成。

Mod 预览 `cover(game,id)` 返回 data URL 或 null，`chooseCover(game,id)` 返回快照或 null，支持可解码 PNG/JPEG/WebP/GIF。角色图 `characterCovers(game)` 返回角色名到 data URL 映射，`chooseCharacterCover(game,name)` 返回快照或 null，仅可解码 PNG/JPEG、最大 10 MB；拒绝 WebP/GIF或解码失败保留原图。默认角色资源的格式不等于自定义图选择限制。

## 事件与当前消费者

`onDesktopChange(callback:(event:DesktopChange)=>void):()=>void` 签名及 payload 未变，解除订阅函数应在消费者卸载时调用。`DesktopChange={gameId:GameId,settingsChanged:boolean}`；gameId 表示通知发生时当前选中上下文，并非每次操作参数游戏的回执。Mod/角色图变更沿用已有刷新通知，settingsChanged 为 false；设置切换、保存与 P1 部署/同步保存配置的通知为 true。队列内广播保证相关读取与操作协调；取消也可能沿已有刷新路径发通知，不能以收到事件作为写入成功证据，成功/错误/取消应看本次 Result。

当前实际业务消费者为 ModPage、CharacterGallery、FloatingView；SettingsPage / DesktopSettings / App 消费设置与游戏切换接口。P2 现有消费者继续兼容。后端与 bridge 的两游戏、图片、取消、部分成功、重启、实际归档与副本证据已通过；当前窗口不证明真实游戏加载。

## P3：INI 字节上限与业务刷新通知

P3 没有签名或 payload 变更。`saveIni(game,id,relativePath,digest,edit)` 仍返回 `Promise<Result<IniDocument>>`；`edit` 是 `{kind:'text',text:string}` 或 `{kind:'keys',keys:IniKey[]}`。保存继续校验读取时 digest，保持原编码、BOM、原换行以及快捷键编辑未涉及的字段和注释。新增统一 4 MiB（4,194,304 字节）上限，按最终编码 Buffer（包含 BOM、换行归一化结果）判断；text 与 keys 都适用。超过上限返回错误，在创建副本和写原文件之前拒绝，不再出现“返回失败但原文已改变”。恰好上限可保存；不支持的编码、过期 digest 等原拒绝语义保持。

以下已有调用成功后现在也通过现有排队广播发送 `desktop:changed`，两窗应重读相关数据。错误不广播；没有增加新事件类型。

| 方法与签名 | 返回 value | P3 新通知 |
| --- | --- | --- |
| `savePreset(game:GameId,id:string|null,name:string,members:Record<string,boolean>|null)` | `Preset[]` | `settingsChanged:false`；保存/创建预设后刷新 |
| `deletePreset(game:GameId,id:string)` | `Preset[]` | `settingsChanged:false`；删除预设后刷新，Mod 文件保持 |
| `saveIni(game:GameId,id:string,relativePath:string,digest:string,edit:IniEdit)` | `IniDocument` | `settingsChanged:false`；保存后刷新候选报告/恢复记录等 |
| `createBackup(game:GameId,name:string)` | `RecoveryItem[]` | `settingsChanged:false`；完整快照创建后刷新恢复列表 |

这四方法均为 `Promise<Result<表中value>>`。事件 gameId 仍是通知时当前 selectedGame，并非操作参数游戏；生产两窗测试已验证选中 zzz 时操作 endfield，两窗收到 `{gameId:'zzz',settingsChanged:false}`。已有 applyPreset 的 `{library,issues,applied}` 部分结果保留：缺失或受停用父级阻碍的成员列入 issues，其它成员继续处理；新非成员保持原启停，稳定 ID 跨改名/分类仍匹配。候选 hash 只检查有效启用 Mod 与启用 INI 中的 override 字面值，不代表已确认渲染错误。

Cursor 注意：收到刷新通知不等于放弃未保存编辑；保留当前同身份预设/INI 草稿，更新未编辑的展示数据。INI 外部被改时继续依赖 digest 拒绝陈旧写入，提供明确重新读取入口，不自动用旧内容覆盖。当前真实双窗已验证预设名称草稿、打开编辑器的 INI 文本在外部保存通知后保持；未扩大为所有页面草稿路径验收，也没有修改 renderer。证据 `.run-data/modules-review/phase3-bridge/run-cPRBXO/report.json`；原通知缺失和先写后报错基线为 `phase3-broadcast-baseline/run-kuPbSj/report.json`（运行修改前已构建产物）。四编码/双游戏 inclusive 边界与拒绝原文/副本不变见 `tests/ini-size.test.ts`。

## P4：已实现的兼容局部保存接口

后端契约、typed preload、受信任 queued handler、纯 merge/validation helpers 已接通。**SettingsPage 与 DesktopSettings 已接入**，清单状态为 connected。新增兼容方法没有删除或改变旧方法签名。

| 新增接口 | 返回 | 兼容与保存规则 |
| --- | --- | --- |
| `saveGamePaths(game:GameId, patch:Partial<GamePaths>)` | `Promise<Result<Settings>>` | `settings:save-game-paths`；主进程队列内读最新配置、白名单验证、仅合并指定游戏字段；不切 selectedGame |
| `saveDesktopPreferences(patch:Partial<DesktopPreferences>)` | `Promise<Result<Settings>>` | `settings:save-desktop-preferences`；同队列内仅合并桌面偏好，不改两游戏路径或选择 |

`saveSettings(settings:Settings):Promise<Result<Settings>>` 保留完整替换语义。设置页和桌面设置已不再 read → full save；该旧方法当前无页面消费者，清单为 compatibility-only，其本身仍不是并发安全的完整替换。`selectGame` 仍是原子切换选中游戏的方法，保存路径不能代替它。部署/同步原签名保留，继续在主进程按操作游戏保存结果。

| patch | 允许字段及值 |
| --- | --- |
| GamePaths | `xxmiRoot/gameDirectory/modsDirectory`，string，trim 后为空或完整绝对路径；最大 32767 字符，不含 NUL；只保存配置，不要求目录已存在、不自动同步 loader |
| DesktopPreferences | `marketUrl/updateUrl`，string，trim 后空值或不含账号密码的 HTTP(S)，最大 4096 字符，不含换行/NUL；允许 `{gameId}` 占位符。`closeToTray` 只能 boolean |

patch 必须为非空普通字段对象；`{}`、null、array、未知字段、undefined 或错误字段类型、无效路径/URL 都返回 `{ok:false,error}`，原配置 bytes 保持、不发送通知。`''` 是显式清空值，省略字段表示保留；不能用 undefined 清空。原 desktop 缺省时局部保存从空 URL、`closeToTray:true` 合并。两个接口无取消或部分成功：整份 patch 校验通过才保存，成功返回完整当前 Settings，并向两窗发送 `settingsChanged:true` 配置重读提示。gameId 仍为当前 selectedGame。事件 true 不是所有通道实际写入的证明，例如旧 restore 取消也可能提示重读，仍以本次 Result 判断业务结果。

### 已接入的页面

- `SettingsPage.tsx` 的保存配置提交当前游戏 dirty 路径，不把其它游戏草稿、desktop 或 selectedGame 包进请求。检测、同步、部署仍走原接口，不把未验证路径保存当成部署成功。
- `DesktopSettings.tsx` 只提交改过的偏好。表单未改时本地反馈「无待保存更改」，不调用 `{}`。
- `settings-draft.ts` 导出 `dirtyPatch`、`acceptSubmittedGamePaths` 和 `acceptSubmittedPreferences`。外部事件重读后只更新未编辑字段；自己成功后只接受本次提交且尚未被再次编辑的字段。其它游戏或其它偏好草稿继续保留。
- `App.tsx` 继续用 `selectGame` 切游戏，并接收完整 saved Settings。只在 `settingsChanged` 时重读，与当前字段草稿合并。事件 gameId 不是操作参数回执。订阅在卸载时解除。
- `ModPage` 与 `CharacterGallery` 已同时呈现导入成功数和完整错误；新的选图操作清除旧成功提示。`BusinessPage` / `IniEditor` 不使用这两个新增保存方法。

下面与当前导出函数一致。页面在自身保存期间禁用相关输入；等待期间再次编辑仍由 helper 测试覆盖，没有通过强行启用控件当作正常操作验收。

```ts
// dirtyPatch、acceptSubmittedGamePaths、acceptSubmittedPreferences 均从 settings-draft.ts 导出。
const game = selectedGame; // 捕获提交身份，异步返回时不得改变用户当前选择
const submitted = dirtyPatch(configuration.draft.games[game], configuration.baseline.games[game]);
if (!Object.keys(submitted).length) return; // 本地反馈「无待保存更改」
const result = await window.kmm.saveGamePaths(game, submitted);
if (!result.ok) { setError(result.error); return; } // 保留全部草稿
// 仅本次提交且当前草稿仍等于提交值的字段采用 saved 的规范化值；
// 异步等待期间再次编辑的字段保留，其 baseline 更新为 saved，继续 dirty。
setConfiguration(previous => acceptSubmittedGamePaths(previous, result.value, game, submitted));
onSaved(result.value);

const preferencePatch = dirtyPatch(desktopDraft.draft, desktopDraft.baseline);
if (!Object.keys(preferencePatch).length) return;
const savedPreferences = await window.kmm.saveDesktopPreferences(preferencePatch);
if (!savedPreferences.ok) { setError(savedPreferences.error); return; }
setDesktopDraft(previous => acceptSubmittedPreferences(previous.draft, previous.baseline, desktopPreferences(savedPreferences.value), preferencePatch));
```

### 实际清单与验收

`npm.cmd run api:inventory` 用 TypeScript compiler/AST 生成清单；`npm.cmd run api:check` 拒绝 main/preload/shared 编译错误、重复/漏映射、preload/handler 不一致、未批准消费者缺失，以及清单和当前源不同。参数/Result.value、注册、服务入口/调用和真实消费者由 AST 派生，取消/部分成功说明为审查过的语义 metadata。两个局部保存方法当前消费者分别为 SettingsPage、DesktopSettings，状态为 connected。旧 `saveSettings` 无页面消费者，状态为 compatibility-only，仍保留完整替换契约。尚无消费者的已批准新方法才标 awaiting-cursor；其它旧方法缺消费者仍拒绝，不需为合法迁移改生成器。`ipc-contracts.ts` 为 type-only 对应；sandbox preload 编译后只 require Electron，未引入共享模块运行时 require。

| 场景 | 后端/API 状态 | Cursor 页面验收 |
| --- | --- | --- |
| 主/浮窗并发保存两游戏不同字段及桌面不同字段 | 迁移前生产 IPC PASS，所有字段与 selection 保留，成功完整 Settings + 两窗 true 事件 | 页面已不再 read→fullsave。本轮页面验收确认主窗只提交当前游戏 dirty 路径和 dirty 偏好；未把每一种双窗表单并发排列重跑为压力测试 |

| 另一游戏/偏好仍 dirty 时保存当前字段 | API 保留持久字段 | 页面已验收：提交字段接受规范化值，其它草稿保留，外部未编辑字段更新 |
