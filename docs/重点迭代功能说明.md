# 重点迭代功能说明

更新日期：2026-10-13。三项优先功能已接入服务、生产 IPC 和实际页面：多选与批量管理、角色外观互斥组、Mod 来源与版本记录。此次不生成新便携包、不执行安装或 Release 下载验证，不运行真实游戏。正式后续版本号仍按发布安排确定。

## 多选与批量管理

Mod 库每行有独立复选框，勾选不会改变当前详情身份。全选只增加当前筛选结果；清空选择清除全部；筛选外选择保留，界面明确显示总选择数和筛选内数量。批量操作作用于全部已选项。

- 批量启停：返回每项成功、错误和互斥处理说明，不能把部分成功当整体失败。
- 批量分类移动：提交 category/character/appearance，移动实际目录，保留作者、说明、稳定 ID、来源记录和本身停用状态；留空表示清空对应标签。移出停用祖先可能重新启用内容，同样受互斥选择约束。
- 加入预设：按所选 Mod 的实际启停状态合并到已有预设，保持其它成员；也可仅从所选创建预设。
- 切换游戏、已保存目录或离开该页面会清理选择；同库刷新按稳定 ID 保留仍存在的选择。

接口 `batchMods(game,ids,operation,choices?)` 返回 `{library,items,conflicts}`。ids 为 1–5000 个不重复 ID；operation 只允许 toggle/classify。未知/其它游戏 ID 在逐项结果中报告失败。参数整体格式非法时拒绝整个请求；正常逐项文件错误不影响其它项。`conflicts` 非空时尚未执行任何文件操作，items 为空；用户选择或取消后再执行。

## 角色外观互斥组

手动建立组并选择成员，不依据角色名推断服装/配件是否互斥。每组至少两个成员，一个 Mod 只属于一个组；按游戏和当前库目录保存。删组只删除规则，不改文件或启停。

保存组时如果有多个实际启用成员，必须明确选择保存时启用的成员；否则保留当前状态。启用一个成员时，先核对目标和同组其它成员的启停目标，再停用其它有效启用成员。目标受停用祖先或同名目录阻挡时，保持原启用成员；切换中失败时尝试恢复已停用成员，回退不完整会明确报告。

主窗单项、浮窗、批量、预设都共用此规则。移动或恢复让组成员重新启用时也遵守组约束。批量/预设同组请求启用多个成员时返回候选列表，页面要求用户选一个；不依赖执行顺序静默决定。未选择前不改文件；选择后其它请求启用的同组成员改为停用，并在结果中说明。未涉及的预设非成员通常保持；与新启用成员互斥的非成员会停用并报告。

外部手工改目录或文件占用可能造成实际状态与规则冲突，扫描会显示警告。这是本地文件管理规则，不证明真实游戏加载/渲染效果，也不宣称全局中断事务或大规模性能验收。

接口：

- `saveExclusiveGroup(game,id|null,name,modIds,enabledId?)` → LibrarySnapshot。
- `deleteExclusiveGroup(game,id)` → LibrarySnapshot。
- 组列表在 `LibrarySnapshot.exclusiveGroups` 中读取，无独立读取接口。
- `applyPreset(game,id,choices?)` 新增兼容可选参数；结果新增 conflicts，applied=0 表示因互斥选择尚未执行；issues 保留失败/互斥处理说明，与成功数量同时呈现。

## Mod 来源与版本记录

独立于 metadata 的 `provenance` 字段包含来源 HTTP(S) URL、Mod 版本、适用游戏版本、人工验证状态、导入时间和版本历史。

- 来源地址可以留空，拒绝凭据、危险协议、换行/NUL；打开来源根据已保存游戏/ID 重读地址，由默认浏览器提交请求。
- 版本和适用游戏版本是最多 120 字符的单行文本，不强制 Mod 作者采用管理器的版本格式。
- 验证状态为 unverified/verified/broken，界面显示待验证/人工已验证/已失效，均是人工记录。
- 管理器成功导入时记录时间；旧记录或外部发现的 Mod 不伪造导入时间，显示未知。
- 修改信息时保存修改前记录；无变化的保存不增加历史。
- 替换内容时保留替换前来源、版本和验证记录；新内容保留来源，版本与适用游戏版本清空，状态重置为待验证，等待用户填写。稳定 ID、metadata、预览和本身停用状态保持。
- 改名、分类、重启、恢复副本及完整快照保留对应记录。恢复所选旧内容时恢复其旧记录；覆盖前副本仍保留当前记录。

保存通过 `operateMod(game,id,{kind:'provenance',fields})`，只接受四个可编辑字段。历史和导入时间由后端维护，不由 renderer 指定。`openModSource(game,id)` 只根据已保存地址打开网页，不接收任意 URL。

来源表单按游戏/稳定 ID 和逐字段基线保留未保存草稿，保存结果仅接受本次提交且期间未被再次编辑的字段；其它业务刷新不保存这些草稿，也不清空原详情的作者/名称编辑。

## 数据与接口维护

`library-<game>.json` 继续使用 version:1，新增可选 exclusiveGroups 和 record.provenance。旧数据无这两个字段时仍可读取，快照已有 library.json 和恢复 sidecar 自动包含新字段。

新增五个异步接口：batchMods、saveExclusiveGroup、deleteExclusiveGroup、openModSource、addModsToPreset；operateMod 和 applyPreset 兼容扩展。当前合计 49 个异步方法 + 1 个可解除事件，所有新增方法均有实际 renderer 消费者。主进程队列和双窗刷新通知覆盖新修改；单项/组保存/恢复发生异常时也请求重读实际状态，避免隐藏可能的部分文件修改。

实现位置：`mods.ts`、`exclusive-groups.ts`、`mod-provenance.ts`、`business.ts`；页面为 ModBatchTools、ExclusiveGroupsPanel、ModProvenancePanel、ExclusiveChoiceForm 及现有 ModPage/BusinessPage/FloatingView。
