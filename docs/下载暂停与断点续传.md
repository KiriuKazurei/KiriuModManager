# 下载暂停与断点续传

下载中心的 Mod 新安装包与 Mod 更新包共用本功能。下载中可点击“暂停”，已暂停任务可按“已暂停”筛选。存在可靠片段时显示“继续下载”；重新打开管理器不会自动联网恢复。

暂停和中断时，管理器在原任务专属缓存中保留片段。下载期间每两秒至多追加一次已收到的新字节，暂停／退出时再保存一次；每次先同步片段，再原子保存偏移、SHA-256 和来源记录。片段与当前下载文件最多各占一份空间，磁盘不足或权限错误会禁用无法证明的续传。异常退出以最后完整落盘的片段为准，尚未提交的尾部不会直接拼接。

继续时先校验片段摘要和网站的游戏、Mod／文件 ID、大小及已有摘要，再向受支持来源发送 Range 探测。要求 206、匹配的 Content-Range、强 ETag 和 Last-Modified，重定向仍限于允许的 GameBanana HTTPS 域名。失败时保留片段并提示稍后重试或重新下载。服务器不支持或资源已变化时不会静默丢掉旧片段后从零下载；“重新下载”是明确操作，并创建新任务。

原生恢复事件没有 WebContents。只有主进程刚登记恢复、缓存路径精确匹配、URL 链一致的事件才能绑定到原任务；普通网页下载继续执行原来的来源检查。延续原登录会话，但 Cookie、缓存路径及恢复 URL 不暴露给 renderer。

继续保持原任务 ID、游戏、安装目录和更新目标；最多三个活动任务，已暂停任务释放名额。目录改变后下载仍可完成，安装沿用既有目录确认规则；定向更新不改绑其它目标。完整包通过原有大小和摘要验证后进入待安装，新安装仍需预检，更新包仍需确认替换，不会自动安装。

取消会终止任务并删除该任务的自有恢复片段，不提供取消后的继续。完整包、历史记录和既有 Mod 不受此操作替换。旧版 tasks.json 可读取；旧任务缺少恢复信息时继续使用重新下载／已有完整包的重试流程。

接口通过既有 `modDownloadAction(id,'pause'|'resume')` 调用。`ModDownload` 增加 paused/resuming 及可选 canPause、canResume、resumableBytes、resumeMessage；不能将能力字段理解成服务器可用或游戏内生效保证。其它一次性失败仍使用统一提醒窗口。

验证命令：`npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run api:check`、`npm.cmd run build`、`npm.cmd run smoke:download-resume`。原生专项使用 Git for Windows 的 OpenSSL 生成仅本次隔离样本证书，以进程内域名映射连接回环 HTTPS，不修改系统证书、hosts 或真实账号；覆盖暂停、新进程恢复、未清理退出恢复、服务器 Range／Cookie 和实际下载页生产 IPC。不启动真实游戏，不下载真实 Mod。

设计与验收矩阵见[实施计划](下载暂停与断点续传实施计划.md)。管理器自身更新包暂停／续传不在本次范围。
