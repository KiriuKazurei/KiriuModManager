## 普通预设应用前预览（F02）

预设详情点击“预览应用预设”，显示将启用、将停用、保持不变、缺少成员、父目录阻挡及预设外互斥／依赖联动。存在未保存的名称／成员时，明确选择“保存编辑后预览”或“使用已保存预设”。

- 同组请求启用多个成员时，先选一个并更新预览，不直接执行。
- 缺少成员默认阻止执行；用户可明确排除该成员并重新预览。外部清单保留的缺失成员显示名称，不使用伪造的本地 ID。
- 父目录停用与自身目录停用分别处理：请求停用仍可能改变自身目录名；请求启用遇到停用祖先时阻止执行。
- 未知版本及联动停用须接受本次提示，缺失前置／低版本等阻断不能绕过。预设外的变化逐项列出。
- 预览只读业务文件。确认时原生再次提示游戏、已保存根和变化数量，进入同一写队列复核预设、路径、目录身份、依赖／版本和短期凭证。取消不修改文件，也不使有效预览误报过期。
- 普通预设只改目录启停，不写 INI；活动独立配置关联保留，差异可显示为脏状态。目录变化使用受限 v2 `preset-switch` 提交，失败整组回退；外部修改使回退不可靠时保留中断记录。

旧 `applyPreset` 兼容入口也走同一解析器和主进程确认。原独立配置档继续使用已有配置预览／备份／切换流程。

## 清单记录与导出（F12）

预设页“导出预设清单”先展示内容，再选择保存位置。默认输出 `*.kmm-preset.json`，格式为 `format: kmm-preset`、`schemaVersion: 1`，按游戏隔离。

| 字段 | 记录内容与用途 |
| --- | --- |
| `members[].id`、`key`、`name` | 导出时的本地 Mod ID、文件内成员 key 和可读名称；跨库导入重新映射当前本地 ID |
| `enabled`、`version` | 预设保存的启停选择与声明版本；导入清单本身不应用这些状态 |
| `source.provider / modId / fileId / entryPath` | 网站来源、站点 Mod ID、文件 ID 和包内条目身份 |
| `source.downloadUrl / sourceUrl` | GameBanana 对应文件下载链接和详情链接，使用 ID 构造的规范地址，不附带账号或 Cookie |
| `hash` | `mod-tree-v1`、SHA256、文件数、逻辑字节数及路径／大小结构摘要；本地导入的 Mod 必须记录，网站 Mod 也附带内容哈希 |

内容哈希覆盖 Mod 内全部普通文件的相对路径与原始字节，包含 INI、封面和资源；只去掉最外层 Mod 目录名。因此改名／顶层启停不改变摘要，修改热键、封面或资源会改变摘要。内部子目录名仍有意义，不按名称或网站声明版本冒充内容一致。

导出只包含明确选择的预设信息。收藏、标签、人工兼容性标记、机器根路径、日志、Mod 资源和登录凭据不导出。保存目标不能位于数据目录及任一游戏、Mod 或加载器目录；唯一暂存文件原子提交，取消／目标在准备期间变化时保留原文件。

## 导入、缺失名称与不同哈希替代

“导入预设清单”由主进程原生选择本地 JSON／配置 ZIP，不自动访问链接或下载 Mod。

1. 内容哈希唯一一致时建议映射；同站点 Mod／文件／条目作为关联依据。只有名称或声明版本相同不能自动认定是同一个 Mod；多个相同副本要求用户选一个。
2. 找不到可接受映射时，明确列出 **缺少的 Mod 名称**，并保留其来源、下载链接和哈希。没有替代项就继续显示缺少。
3. 可选择当前库内任一合适 Mod 作为替代，也可通过原生选择器导入替代文件夹／ZIP／7z／RAR。此入口新导入的 Mod **默认停用**；压缩包内多项分别报告，已存在的同名目标保持。
4. **允许哈希不同的 Mod 替代**。选择后明确勾选接受哈希不同／未比较替代，再“重新核对匹配”。不同外部成员不能指向同一本地 Mod；全局互斥／依赖声明不会被导入覆盖。
5. 未补齐时可明确保存待补齐清单，`Preset.missingMods` 保留缺失名称／来源／哈希；有效本地 ID 只进入 `members`。全缺失时页面标为待补齐清单，不能作为有可用成员的预设应用。
6. 选择该清单后“补齐所选清单”可继续匹配，重启也保留缺失记录。普通新导入创建新预设，不覆盖已有同名预设；补齐操作仅更新用户明确选中的待补齐清单。

若旧 Mod 已被用户从磁盘移走，又导入同文件夹名但内容不同的替代项，新项获得新 ID；旧缺失记录保留失效标记，原有其它预设不会悄悄改绑到替代内容。该标记不表示存在恢复副本。

清单导入只保存组合／匹配结果。现有 Mod 的物理启停、INI、来源、收藏、标签、人工兼容性和活动配置保持；用户之后通过 F02 预览并确认应用。

## 可选独立 INI

独立配置预设可显式勾选携带已保存 INI，输出 `*.kmm-profile.zip`；只允许 `manifest.json` 和 SHA256 命名的 INI 字节副本。INI 可能含私人参数或注释，导出前需要用户明确选择。

使用 `profile-compatible-v1` 投影证据：在源端和目标端逻辑上把明确捕获的 INI 替换为相同保存字节，再比较整份文件树；不改磁盘。资源、路径或其它非捕获文件不同，则阻止携带原独立配置。**不同哈希的替代仍可用于启停清单**，不能据此宣称原 INI 一定兼容。

只有成员完整、配置路径／字节摘要和资源投影一致，才允许导入独立 INI。接收时映射为目标库的本地 ID／内容修订，创建**非活动修订**，不覆盖当前运行配置。配置与预设引用使用狭义 `preset-import` 持久提交：最多创建一个新 UUID 配置修订目录，只写该游戏的预设索引；未完成提交通过现有恢复服务处理。

有缺失或不适用配置时，可以保存启停清单并保留原 ZIP；待补齐清单记录成员信息，未接受的 INI 副本不会自动迁移。需要携带原 INI 时，补齐后重新导入原 ZIP。

## 边界与接口

共享只读任务最多两项，支持进度、取消和游戏／请求上下文核对；结果与短期确认分开，不用长时间全局 busy 锁住哈希读取。哈希最多 8 GiB／任务，单 Mod 最多 50,000 节点／32 层，匹配盘点最多 200,000 文件；按结构索引候选，每项内容仅在当前任务内计算一次。预算不足显示未完成比较，手动接受替代不会被标为内容一致。

JSON 最多 4 MiB／5,000 成员；独立配置最多 2,048 项、单 INI 4 MiB、INI 总量 64 MiB；ZIP 输入 80 MiB、实际输出 68 MiB／2,049 文件。拒绝重复 JSON key、非法版本、跨游戏、路径穿越、链接、额外 ZIP 文件及摘要不符。读取未索引的磁盘目录时不临时生成内容修订或写库，匹配需要先在 Mod 库扫描取得有效本地身份。

新增八个主窗调用，该增量当时为 **88 个异步方法 + 1 个事件**，F01 接入后当前为 93 + 1。远程网页无权访问，浮窗不能创建或执行这些预览／清单任务。参数、成功 DTO 和取消语义见[桌面接口文档](桌面接口文档.md)、[AST 自动清单](desktop-api-inventory.json)。`Result.details` 仍只表示依赖计划。
