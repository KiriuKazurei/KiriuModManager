更新日期：2026-10-15；当前源码 **0.0.5**。本文是当前桌面 API 和业务调用规则的权威入口：**99 个异步方法 + 1 个可解除事件订阅**，其中 93 项有 renderer 消费者，6 项兼容保留。布局/组件、页面导航、草稿、缓存及验收矩阵见[前端功能与 GUI 对接文档](前端功能接口调整需求.md)，从旧接口迁移见[接口调整说明](接口调整说明.md)。

当前产品源码基线 e15f958 已提交并推送远程 main；旧版本说明中的 40/55/65/80/88 是对应阶段记录，不是当前接口总数。0.0.5 包含 F13 路径修复 R1–R3 的 4 项方法及独立开发 SDK；路径修复原本地提交为 5b0a169，本次随 0.0.5 一并同步。

SDK 0.2.0 新增 Windows 进程重启/恢复独立范围；产品设置页新增本地兼容记录提示与两项受限 API。SDK 的启动/终止权限仍只在开发 CLI，不向 renderer 暴露。功能开发起点为本地 `agent/main` 的 `12beff7`，交付目标为开发主分支 `agent/main`，实际提交与推送状态以 Git 引用为准。接口与功能映射见 [SDK 使用说明](../dev/compat-sdk/README.md)和[进程恢复与兼容提示](进程恢复与兼容提示.md)。

## 1. 调用契约与权限

生产流程：window.kmm → typed preload → 受信任主进程 handler → 本地服务。没有 HTTP 产品后端。入口见 [contracts](../src/shared/contracts.ts)、[IPC 映射](../src/shared/ipc-contracts.ts)、[preload](../src/preload/index.ts)、[main](../src/main/index.ts)；完整位置、服务调用和消费者见[AST 清单](desktop-api-inventory.json)。

```ts
type GameId = 'zzz' | 'endfield';
type Result<T> = { ok:true; value:T }
  | { ok:false; error:string; code?:string; details?:DependencyPlan };
type DesktopChange = { gameId:GameId; settingsChanged:boolean };
```

所有异步方法为 Promise<Result<T>>，下表结果仅写 T。Result.details **只代表 DependencyPlan**，不能用它承载恢复/导入/清单 DTO。成功、取消和部分成功以本次返回值判断，不凭事件或 toast。

只接受已注册主/浮窗的可信文档 main frame；拒绝外部页面、子 frame、导航后的来源。远程 WebContentsView 无 preload/Node/桌面接口。sandbox preload 运行时仅 require Electron，共享 IPC 映射为 type-only。

| 仅允许可信主窗 | 说明 |
| --- | --- |
| mod-import:*、mods:import | 新预检及兼容导入 |
| preset-manifest:*、presets:preview/commit/apply | 清单、新普通预设及旧应用 |
| inspection:*、diagnostics:*、conflicts:details | 包括 inspection:read/cancel/reveal |
| recovery:create/restore/protect/prepare-restore/apply-restore/prepare-cleanup/apply-cleanup/cleanup-job | 备份、恢复、保护及清理；旧 recovery:list 只读未设此限制 |
| market:*、desktop:link 的 market 分支 | 获取Mod和下载 |
| environment:* | 游戏环境检查、原生选择、修复及回退；禁止浮窗使用 |
| compatibility:* | 读取环境适用性、原生选择本地测试记录；不启动进程 |
| desktop:window-theme | 主窗原生栏主题 |

其它通道仍先验证可信主/浮窗，不代表浮窗已有对应 GUI；当前消费者列明实际接入点。window.kmm 不暴露任意文件读取/删除、EXE 执行、Cookie 读取、任意网页导航或任意下载 URL。

### 同一接口内的不同业务操作

`operateMod` 的 `operation.kind` 不是通用字段保存；GUI 必须按对应功能构造完整的联合类型：

| kind / 参数 | 对应功能与实际效果 |
| --- | --- |
| toggle / enabled | 启停物理目录；启用时处理互斥成员及依赖联动，停用祖先可能阻挡启用 |
| rename / name | 实际改目录名，保留稳定 ID 和自身停用前缀；同名不覆盖，纯大小写变化也提交 |
| classify / category,character,appearance | 按分类/角色/外观移动目录，并更新这三项标签；允许空标签，不能移动到另一 Mod 内部 |
| metadata / metadata | 保存完整 category/character/appearance/author/description 字段，不移动目录；不是 Partial patch |
| provenance / fields | 保存来源地址、声明版本、游戏版本和人工验证状态，后端维护导入时间及变更历史；不改 remote 站点身份 |
| favorite / value | 保存当前 Mod 的收藏 boolean，不改变文件或启停 |
| tags / values | 验证/规范化并保存该 Mod 标签数组，不是新增某一标签的增量请求 |
| requirements / value | 保存依赖/版本声明并检查依赖图；已启用项还要核对拟声明是否可成立，不自动安装依赖 |

`batchMods` 仅支持 toggle 和 classify；它按成员返回结果，不能套用普通预设的目录原子提交承诺。批量全选范围与隐藏选择由 GUI 明确展示，接口使用提交的稳定 ID。

| modDownloadAction.action | 对应功能与实际效果 |
| --- | --- |
| cancel | 仅取消 binding/downloading/verifying 阶段的下载；安装提交中拒绝，F01 停止剩余项用 discardModImport |
| retry-download | **发起新的原生下载并创建新任务 ID**，原记录/缓存保留；保留原游戏，新安装任务读取该游戏此时保存的 Mod 根；定向更新继续使用固定 updateTarget.root |
| retry-binding | 在原任务重新读取网站文件绑定；有完整包再校验到 ready，没有包则提示重新下载；不静默更改原任务根或安装 |

“已有任务的目录固定”指同一任务记录，不表示重新下载创建的新记录沿用旧根；旧完整包仍需经过 install-current 的明确选择才可改根。

## 4. 取消、错误、部分结果和依赖确认

- 原生选择/确认取消多为 ok:true,value:null：目录、封面、替换/移除、恢复、清理原生动作、更新下载/安装、预设提交/导出和新预检准备/提交。cover 的 null 特指没有图片，不是取消。
- 兼容 importMods 和 importPresetReplacement 取消为 ImportResult.canceled:true；即使 errors 非空也要同时呈现 importedIds。F01 回执再按 items.state 展示；全部跳过也不等于失败。
- batchMods.conflicts 非空时先明确互斥选择再重试；未选择不按顺序覆盖。处理逐项失败，不能只判断 IPC.ok。新普通预设改选择/排除后重新预览。
- Result.code===DEPENDENCY_CONFIRMATION 时，details 为 DependencyPlan。有 block 不可确认越过；仅 warning 经本次明确接受后以 {token,acceptWarnings:true} 重试原调用。token 过期、根/文件/修订变化都需重读。
- 新图片选择前清旧成功提示；null 不显示已保存。错误保留相关草稿；成功采用真实返回名称、ID、字段，不构造乐观文件结果。

## 5. 后台任务、预览和提交

InspectionKind 为 diagnostics/inventory/conflicts/restore-preview/preset-preview/preset-export/preset-import/mod-import。InspectionJob.stage 为 running/complete/canceled/error。共享预算最多两个；同 kind/game 运行时只有同 requestKey 可复用，其它或正在取消的请求拒绝。结果最多 20 条，非运行项到期 10 分钟清理；取消请求标 stale，实际退出后才变 canceled。

诊断/盘点/冲突/预设准备在后台运行，F01 准备会写归属缓存而不写库。任务创建固定上下文；短 token 通常两分钟且提交重新验证；不要在 renderer 持久保存 token 当权限。stale/incomplete/unknown/warnings 应展示，不能隐藏后继续执行。

写入与关联读取经主操作队列；状态、窗口、部署/更新进度、market、文件清单/停止、inspection read/cancel、conflictDetails、cleanup-job 等响应通道不被长队列堵死。响应通道内部的实际安装/清理提交仍回到共享队列。安装管理器更新前检查导入、恢复清理、Mod 下载/安装活动；installing 时仅保留 update:status 与 desktop:status/show/quit。

F01 新装：prepare → revise（修改后）→ commit，原生确认取消不消费有效 token。完整树重复默认跳过、同名保护、另存副本需不同目标；未知空间/比较必须显式接受。newOnly 逐项可恢复提交，全新项停用；停止剩余不回滚已完成项。discard 只清证明归属且无引用缓存。详情见[导入说明](0.0.4导入预检与内容去重.md)。

F02/F12：普通预设 commit 只改启停目录，不写 INI；独立配置走 profile 预览/策略/提交。清单导入仅保存预设/非活动修订，缺失名称保存在 missingMods，members 只放真实本地 ID；网站身份/同名不能替代完整哈希，显式允许不同哈希替代。详情见[预设说明](0.0.4预设预览与清单迁移.md)。

恢复以 preview.scope 为实际范围；完整快照为整根，覆盖前副本和根边界必须保留。CleanupJob.phase 为 prepared/working/pending/complete/undone；items.phase 为 planned/moving/staged/deleting/deleted/restored/error。apply 返回任务不是删除完成，继续 read；continue/undo/cancel 有实际逐项边界。import-preparations 只统计/定位，不扩展永久删除白名单。

## 6. 浏览器、下载与新装/更新区分

两游戏共享一个原生 WebContentsView、历史、persist:kmm-gamebanana；首页固定[绝区零](https://gamebanana.com/games/19567)和[终末地](https://gamebanana.com/games/21842)。Cookie 主进程持久/加密保存，无 renderer 读取接口。setModBrowser(null) 隐藏，切游戏改首页，历史可能显示另一游戏页面；task.gameId/targetRoot 独立固定，不能用当前 status.gameId 改任务归属。

下载只接 GameBanana 托管 ZIP/7z/RAR，校验详情游戏、文件身份、大小及站点可用 MD5；无法可靠绑定不安装。最多三项并行，下载完成只到 ready，重启未完成 interrupted，不自动续装。外部网盘手动导入。stage 为 binding/downloading/verifying/ready/installing/waiting-directory/complete/partial/error/canceled/interrupted；archiveReady 独立表示完整包可用，items 区分 existing/安装成功/失败。

ModDownloadAction 为 cancel/retry-download/retry-binding/retry-install/install-current/show-file。cancel 针对下载；F01 导入停止用 discardModImport。新装 retry-install 主进程拒绝绕过预检；使用 prepareModImport(download,taskId)。根改变需 install-current 原生确认，确认只准备新根，仍须显式预检和提交；保留完整包。

定向更新继续用 modDownloadInstallPlan + retry-install，仅一个明确包内条目；目标 ID/game/root/contentRevision 固定。先留旧内容副本，保持整理字段、封面与原启停，更新绑定/版本并将人工兼容设回 unverified；不是默认停用的新装。当前绑定由服务维护，本地替换清文件级 remote，恢复副本保留旧绑定。

页面区域/布局注意原生视图层级，具体 GUI 生命周期见前端文档第 4 节。导航 external 仅打开主进程保存并检查的待打开 HTTPS 链接，不接受任意 URL 入参。

## 7. 设置、文件和更新规则

saveGamePaths 只允许三项路径 string，trim 后空或绝对路径、最长 32767、无 NUL；只保存，不要求存在、不自动同步 loader、不切 selectedGame。saveDesktopPreferences 允许 marketUrl/updateUrl/closeToTray/updateSourceUrl；前两 URL 可空或无凭据 HTTP(S)，支持 {gameId}；更新源可空禁用，或无凭据/占位符/片段 HTTPS。URL 最长 4096，无换行/NUL。

两 patch 必须非空普通对象，拒绝 null/array/unknown/undefined/无效类型和值；整份失败不写文件、不广播；省略字段保留，空字符串清空。saveSettings 保留全量替换，仅兼容，不能称并发安全。部署/同步按操作游戏合并保存；检测不保存；普通管理使用已保存路径。局部保存与草稿示例见[接口调整说明](接口调整说明.md)。

metadata 不移动文件；classify 才移动并允许空 appearance；rename 真改目录并保稳定 ID、大小写，碰撞不覆盖。有效停用祖先可能阻止启用。新增分组仅保存 metadata。Mod 图可解码 PNG/JPEG/WebP/GIF；角色自定义图仅可解码 PNG/JPEG、最大 10 MB。INI digest 过期拒绝，最终编码含 BOM 4 MiB 前置检查，原文/副本不因拒绝改变。

更新源 default 为 DEFAULT_APP_UPDATE_SOURCE 的官方仓库，来自保存的 desktop.updateSourceUrl；updateUrl 是外部发布页，二者不等同。检查固定 release 版本/大小/SHA256/说明，原生确认下载后验证；源变更重新检查。ready 后原生确认退出替换并重启，helper 就绪才进入 installing，旧程序留回退。源码 canInstall:false。四方法不接收 URL/包路径/EXE 参数。见[更新说明](管理器更新与发布说明.md)。

## F13 环境接口业务边界（0.0.4 增量）

类型见 [environment.ts](../src/shared/environment.ts)。EnvironmentReport 是 InspectionJob.result 的 `kind:'environment'` 分支：包含 gameId、paths、observedAt、state、complete、候选、executable、loader 公开路径、issues、分项 capabilities 和修复记录。状态不表示游戏已运行，Mod 库能力独立于启动/刷新。

EnvironmentRepairRequest 为 `{kind:'repair',resultId,candidateId,scope}` 或 `{kind:'rollback',repairId}`；scope 为 save / sync-game / sync-mods。默认仅保存路径；后两项白名单修改所选 importer 的 game_folder，sync-mods 另改确认支持的静态 Include 与对应 Launcher override，保留 Secrets、其它游戏及未知字段。拒绝重复 JSON 键、自定义启动/脚本、多重或动态 Include、未知结构及未经确认的组件版本。

预览返回两分钟 token、实际游戏、scope、公开旧/新值、warnings；不返回配置正文或 Secrets。提交回执包含实际 gameId、repair、最新 Settings 和 warnings；不得按当前侧栏选择猜操作游戏。完整原字节保存在 userData/environment-repairs/<game>/<id>；ManagedReference 的 storage.category 新增 environment-repairs，仅定位本游戏固定目录。environment-staging 保存尚未发布日志的准备副本，此阶段不改外部配置，不自动清理或续作。

游戏解析优先核对安装目录内已知名字，未找到时 discover/启动/同步/刷新/诊断使用受限递归（10,000 项、12 层、5 秒；发现多根共用项数/时间预算）。quick 不递归游戏树；缺失/权限/超预算均保留配置且不等于卸载。候选、路径及外部配置在预览/提交时重新核对；既有 Mod 文件、预设、人工兼容性记录不随路径修复改变。

未完成 prepared/working/pending 修复阻止相关路径保存；部署、同步、游戏启动/刷新、全量快照恢复和管理器退出安装还保守核对两游戏记录，避免共享 Launcher 外部写入互相覆盖。有效 Mod 库仍可本地管理，桌面偏好和打开官方 Launcher 仍可用。回退只在当前设置及文件仍为本次前/后值时写入，保留其它游戏/桌面新值；冲突或损坏保留副本并报错，不自动续作。

新增白名单操作日志 environment:apply，记录内部修复 ID 引用和结果，不写原始路径、配置、账号或 Secrets。R4 游戏版本/兼容性自动判定未接入；游戏每次更新后仍按用户安排实际测试。当前实现、样本和窗口证据见[路径修复与验收](0.0.4路径修复与验收.md)。

### F13 回退收尾补强（97+1 签名保持）

回退预览只返回当前仍待恢复的差异；两分钟 token 绑定当时的记录阶段/归属、对应游戏路径与目标摘要。部分回退后重读会跳过已恢复文件；预览后变动需重新预览。正式回退先持久化 working，中断重启不自动续作；失败保留 pending，明确重试可继续回退剩余项。

修复/回退写设置使用 SettingsStore.saveGamePathsIfCurrent（内部方法，不是 window.kmm API）：队列内读取最新完整配置，只修改该游戏路径；实际替换前比较原始文件 SHA256，外部变更不覆盖。其它游戏/桌面/选择保持最新；无需路径变动时不重写文件。完成回退后再次核对文件和游戏路径。

历史读取验证内部归属和副本；旧目录后来变为 Mod 根不使已完成历史失读。准备和提交回退仍检查当前根、链接及外部内容；不能借历史记录写入受保护目标。详见[最新路径修复验收](0.0.4路径修复与验收.md)。
