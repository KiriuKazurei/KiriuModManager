## 恢复与清理边界

- 完整快照恢复整个 Mods 根、角色封面、Profiles、库／预设和该游戏路径。内容摘要相同的文件也在目录提交范围；快照后新增内容先进入恢复前完整副本，再从当前根移出。其它游戏及桌面偏好保持。
- 单 Mod 恢复覆盖保存位置，移出同身份改名后的别名；恢复绑定、版本、修订、目录状态与保存的配置关联，保留当前仍存在的收藏／标签。INI 按当前稳定身份定位，保存当前原始字节副本后恢复。
- 旧快照缺少 Profiles 时清除无效活动关联；异常预设引用／损坏配置摘要在写入前拒绝，不能假称保留了不存在的配置。
- 源／目标关键 INI 和 JSON 在预算内计算摘要；超大配置显示“未比较”，保留身份／大小／时间证据。目录盘点不完整或依赖阻断不能执行。未比较不能当作内容相同。
- 预览 token 两分钟有效，绑定备份记录／内容、当前文件、根、库／预设、保护与提交状态、组件版本。旧兼容恢复入口也经过同一解析器和原生确认，不绕过预览规则。
- 首次仅永久清理完成且可识别的 `snapshot / mod-delete / mod-replace / ini`，固定在当前数据目录的 `removed/<game>/<uuid>` 和匹配记录。旧根副本可显式清理；库中删除标记不因此复活。
- 用户保护、损坏保护索引、链接、归属／盘点不明、未完成文件操作及同副本清理记录阻止清理。解除用户保护不能绕过系统保护，受保护副本仍可明确恢复。
- 删除前写入独立清理记录，同卷暂存 payload 和 JSON；删除逐文件核对路径和身份，不扩大 FileOperations 的目标白名单，不调用任意路径的递归删除。
- 中断后不自动继续永久删除。完整未删项目可撤回，原位置被占用时停止；开始删除的项目不可承诺撤回。已删除、完整撤回、部分遗留分别报告，移动到暂存不计作释放空间。
- 空间为逻辑字节数；硬链接、压缩和稀疏文件会影响实际释放量。空间查询失败明确未知。

## 框架、数据与接口

底层：`read-jobs.ts`、`inspection-files.ts` 提供有界本地任务、进度、取消、过期与文件证据；`ModService.readonlyScan/readonlyContext` 不迁移索引或归档旧根。

服务：`diagnostics.ts`、`installed-versions.ts`、`recovery-storage.ts`、`restore-planner.ts`、`ini-context.ts`、`inspections.ts`。页面：DiagnosticsPanel、RecoveryPage、ConflictPage、ModSortControl；IniEditor 增加摘要约束的文件／行定位；VirtualList 的锚点保持是可选策略，其它列表保持原策略。

| 数据 | 行为 |
| --- | --- |
| `recovery-preferences-<game>.json` | version 1 用户保护 sidecar；损坏时保留并禁用清理 |
| `recovery-cleanup/<jobId>/manifest.json` | 归属、游戏、固定 ID、文件身份、阶段及逐项结果；重启保留现场，不能由轮转日志替代 |
| 新恢复记录的 `contentInventory` | 可选 version 1 路径／大小摘要、文件数与字节数；不是内容 SHA 校验，旧记录继续可读 |
| `localStorage kmm:display:<game>` | version 1 排序条件；非法偏好回退名称升序，不写库或物理顺序 |
| `logs/operations.jsonl` | 新增保护、恢复执行、清理任务及报告导出结果；只记受限字段、ID、结果及逻辑字节估计，不记录正文／Cookie／URL |

同窗最多两个只读任务，同类同游戏只运行一个；缓存最多 20 项，完成后十分钟失效。公共目录预算 200,000 节点／32 层、遍历并发 4；INI 扫描 4 MiB 单文件、128 MiB 总量、10,000 文件；候选最多 2,000 组／50,000 出现位置，详情每页 30 处、片段合计约 64 KiB。报告最多 2 MiB，日志摘要重新白名单序列化，最多最近 100 行／256 KiB。

清理所选清单合计最多 200,000 节点／64 MiB；超限拒绝确认，要求减少选择。恢复配置引用额外受 10,000 文件／128 MiB 预算及取消约束。触顶、权限和无法识别内容显示部分／未知。

新增 15 个调用，当前 **80 个异步调用 + 1 个事件**。恢复预览创建后台任务，结果为 `job.result = {kind:'restore-preview', preview:RestorePreview}`，再用 `preview.token` 执行。排序没有新增 IPC。旧 `saveSettings / conflicts / recovery / restore` 保留兼容，主页面迁移后对应清单为 compatibility-only。失败的 `Result.details` 仍只表示 DependencyPlan，没有塞入恢复／清理 DTO。

新检查、报告、保护、清理、恢复执行及详情定位只允许可信主窗口；远程浏览器没有桌面权限，浮窗继续使用原启停逻辑。后台清理仍由共享写队列协调，进度／取消保持响应，管理器更新安装不能跨过活动清理。

完整方法和参数见[桌面接口文档](桌面接口文档.md)及[AST 清单](desktop-api-inventory.json)。

## 验收记录与限制

清理的实际子进程终止覆盖两游戏的持久记录完成、payload 半移动、元数据暂存、部分删除和元数据移除；重新构造服务后验证明确撤回／继续，保留外部占用内容，不把部分删除伪装成完整副本。所有清理均使用自建隔离样本，没有清理真实用户副本。
