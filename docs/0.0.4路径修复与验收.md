# 0.0.4 路径修复闭环与验收

更新日期：2026-10-15。F13 的 R1–R3 已在本地工作区实现，版本保持 **0.0.4**。原设计见[优化方案](游戏版本更新与路径健壮性优化方案.md)，当前正式接口见[桌面接口文档](桌面接口文档.md)。本轮路径修复与收尾作为本地提交保存，未推送远程；远程基线 f572bd9 不含这部分实现。

## 已实现行为

设置常规页新增“游戏环境”：轻检查、查找候选、原生选择游戏/XXMI 位置、明确选择候选与范围、公开差异预览、原生确认提交、记录及预览回退。默认只保存路径，可另选同步 Launcher 的游戏路径，或同时修复确认支持的静态 Mod 读取规则。只读检查和预览不保存业务配置，取消不提交。

绝区零支持 ZenlessZoneZero.exe / ZenlessZoneZeroBeta.exe，终末地支持 Endfield.exe。统一解析器由启动、同步、诊断、刷新共用：优先安装目录内固定名字；无匹配时受限递归，要求唯一结果，多个副本不按时间挑选。发现可以列出多个候选，但提交前须验证所选独立目录。支持目录移动与已知名字，不保证未来未知 EXE 改名自动适配；也不接收任意 EXE 作为启动目标。

quick 只核对固定名字，不遍历游戏资源树。discover 包含已保存游戏根、当前 Launcher 公开路径、本次原生选择、上次明确采用的位置线索，按路径去重；各根共用 10,000 目录项和 5 秒预算，深度最多 12，支持取消。文件和目录都计入预算，不跟随链接、不搜索全盘或管理器数据根，受限/不可读返回 incomplete/unknown。首次挂载/切游戏轻检查；设置环境卡片可见时，对焦点或设置通知去抖 500ms；运行中的发现不被焦点轻检查打断。未增加全局文件监听或游戏版本解析。

游戏、XXMI 和 Mod 根独立。路径失效不清空原设置，不搬迁/启用/替换 Mod；有效 Mod 库仍可管理。环境卡显示 Launcher 目标与读取目录；启动/刷新前强制复核，目标不一致时引导修复。预览及回执绑定实际游戏，保留另一游戏、桌面偏好和 SettingsPage 未提交草稿。

## 写入、回退与范围

四项新增主窗 API 为 checkGameEnvironment、chooseGameInstallation、prepareEnvironmentRepair、applyEnvironmentRepair；当前 97 异步 + 1 事件，91 项有页面消费者，6 项兼容。读取仍复用 InspectionJob 的两并发、取消、状态/过期规则。修复 token 两分钟有效，仅引用主进程拥有的报告/候选/记录，不接受 renderer 任意写入路径。

只修改所选 importer 的 game_folder；sync-mods 还修改单一静态 Include 和对应 Launcher override，要求确认的 XXMI 1.2.0 或以上版本。拒绝重复 JSON 键、未知对象结构、自定义启动/前后脚本、多重或动态 Include。JSON 保留其它字段语义并重新排版；INI 保留无关行/注释。配置与 INI 支持原 UTF-8/BOM/UTF-16 编码，副本保留原字节。未知未来配置语义应通过官方 Launcher 处理，不猜测修复。

专用准备目录 userData/environment-staging/<game>/<id> 在发布完整 journal 前不写外部目标；准备副本暂不自动清理。完整归属、前/后摘要及原字节发布到 environment-repairs/<game>/<id> 后才提交。共享队列串行协调，逐文件 CAS、设置局部合并、提交后复检；同一修复前/后值才允许回退。外部新值、同游戏路径后续改动或损坏记录均拒绝覆盖并保留现场。

重启发现 prepared/working/pending 时不自动续作；相关路径保存受阻，部署、同步、游戏启动/刷新、全量快照恢复及管理器退出安装保守核对两游戏记录，避免共享 Launcher 互相覆盖。桌面偏好、本地 Mod 管理及打开官方 Launcher 仍可用。原子文件替换不是多文件操作系统事务；本轮验证进程强制终止，未进行硬件断电实验。修复历史未加入永久清理白名单，最多读取 100 项/游戏，超限保留现场并提示整理。

日志增加 environment:apply 和内部 environment-repair 引用，不记录路径、账号、完整配置或 Secrets。定位副本复用 revealManagedLocation 的 storage.category:environment-repairs。environment-<game>.json 仅在明确提交后记录位置线索，不是版本事实或写入授权。

## 与原方案的实际边界

R1–R3 的可用闭环已实现。原方案中的可靠游戏版本来源、PE 辅助版本、历史兼容范围判断、文件监听、全局环境提示条等不作为本轮完成项。R4 依用户意见暂不展开；每次游戏更新后仍实际测试并人工确认。不会根据 EXE 时间/指纹宣称游戏版本变化，也不修改人工 verification、预设或互斥组。

原方案的“子目录移动不强改根”保持：若已保存根与 Launcher 一致且唯一解析有效，不自动更改；用户可明确选择独立叶目录再提交。多个正式/测试副本不自动采用。上次位置 sidecar 仅为线索，不是“游戏启动成功”的记录。

## 继续收尾：回退与外部竞争（2026-10-15）

继续复核时新增七项专项测试，复现并修复以下边界：

- 明确回退在第一个文件写入前记录 working；失败记录 pending，重启需重新预览，避免部分回退仍显示 complete。真实子进程在回退第一文件后终止已覆盖。
- 回退预览基于实际当前状态，只列仍需恢复的路径/文件；token 固定当时归属记录、游戏路径和目标摘要，目标或记录变化拒绝旧预览。重试跳过已恢复项。
- SettingsStore 新增仅主进程内部使用的 saveGamePathsIfCurrent：在配置队列内读取最新设置，只合并对应游戏路径，并在替换前比较 settings.json 原始字节 SHA256；外部新值保留，修复安全回退，回退本身失败则保留待处理记录。不改变既有公开 API 签名。提交后再次核对已保存游戏路径，若被外部改选则保留新值并记录待处理。
- 已完成历史读取只验证其受控归属/副本，不因旧 XXMI 位置被改作 Mod 根而阻止未来修复；真正准备/提交回退时仍按当前根/链接/摘要检查，拒绝写入现已受保护的目标。

本轮没有修改 renderer、CSS、App 挂载或四项环境接口的参数/DTO，便于其它 UI 分支合并。版本继续为 0.0.4，R4 和实际游戏运行安排保持。
