# 开发分支约定

2026-10-15 经用户确认，后续开发采用以下分支结构，替代默认的 `codex/` 前缀。

| 分支 | 对应职责 |
| --- | --- |
| `main` | 已整合并验证的稳定源码；发布仍按用户明确安排执行 |
| `agent/main` | 长期开发基线；保留各功能的整合结果 |
| `agent/<主要功能>` | 每次重大功能的独立实现，如 `agent/better-ui`；从最新可用的 `agent/main` 创建 |

Git 不允许裸 `agent` 与 `agent/main` 或 `agent/better-ui` 同时存在，因此不创建 `agent`。已有冲突引用须先核对并明确解决，不删除、重命名或覆盖用户分支。

开始重大功能前核对远程实际引用（包括大小写）、当前分支/工作区和 worktree。更新 `agent/main` 时保留已有开发提交，不重置到 `main`。已有任务正确位于对应功能分支时继续使用它，同一功能的小修不必另开分支。

功能完成后执行适用检查，按已授权范围提交并回流 `agent/main`；用户要求稳定整合时，再将 `agent/main` 合入 `main`。本次用户指定的 `Cursor/ui-better → main` 为直接整合任务，不因新流程改变原授权。

切换或合并不得覆盖他人未提交内容、强占其他 worktree 或用一整侧结果消除业务冲突。需要隔离时使用任务专用 worktree。接口/消费者变化同步对接文档和自动清单；源码、实际窗口、外部集成分别报告。

提交、推送、发布及删除分支按用户当前任务和既有会话授权执行；本约定与技能本身不增加权限，也不要求重复确认已经授权的动作。保留功能分支，不自动强推、删分支或装 Git hooks。

Codex 可使用 `$agent-branch-workflow`。技能包含 `SKILL.md` 和 `agents/openai.yaml`，默认允许自动发现，但只适用于已采纳此约定的仓库或显式调用；不会将本规则强加到其他工程。个人技能安装在 Codex skills 目录，其他机器可依据本文和根 AGENTS.md 执行同样流程。
