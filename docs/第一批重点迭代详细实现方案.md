## 3. 底层框架与数据模型

### 3.1 游戏、根目录和身份

所有数据和计划固定 gameId、已保存 root 与稳定 Mod ID。渲染层传递 ID、相对文件名和选项，主进程解析真实路径；来源检查与下载只接受受控站点 ID，不接受渲染层提供的任意下载 URL。

目录改名和分类移动保持身份；包内容替换生成新的 contentRevision，收藏和标签保持。配置档案按 Mod ID 查找当前位置，避免保存物理目录名作为唯一关联。

根目录改变后，旧计划失效，活动方案归属重新核对。旧配置文件保留，不能自动套入新根；新数据覆盖旧上下文前先保存原库／预设及配置引用的副本。跨库匹配与迁移留给 F12。

### 3.2 库记录的可选字段

继续读取 version:1 库，新增字段可选，旧数据默认 favorite=false、tags=[]、requirements 为空。初次需要配置捕获或换包时补齐内容修订号；无变化的扫描继续避免重写 registry。

```ts
interface PlannedModExtensions {
  favorite?: boolean;
  tags?: string[];
  contentRevision?: string; // 本地内容修订标识，不代表站点版本号
  requirements?: {
    mods: { modId: string; minimumVersion?: string }[];
    components: { component: 'launcher' | 'xxmi' | 'importer'; minimumVersion: string }[];
    gameVersion?: string; // 声明文本，不能据此自动证明游戏兼容
    origin: 'manual' | 'author-stated';
    note?: string;
  };
}
```

收藏必须是布尔值；标签去前后空白并做 Unicode 规范化、忽略大小写去重，保留展示形式，首版每项最多 20 个标签、单标签最多 40 个字符，禁止空标签和控制字符。标签作为纯文本渲染。

前置只能引用同根、同游戏的已注册身份，自依赖、重复依赖和循环关系在保存前拒绝。缺失成员仍保留其声明并显示问题，不能因为扫描不到就悄悄删除要求。

### 3.3 配置档案与预设兼容

在现有 Preset 上增加可选 mode 和 profileRef；没有新字段的预设继续执行原启停语义。档案仍出现在预设页面，避免创建两套重复的方案列表。

现有 savePreset／addModsToPreset 会重新构造预设对象，实现时须保留已有 mode 和 profileRef，不能一次普通改名或成员编辑就丢失配置关联。执行启停以当前 Preset.members 为准；manifest.members 保留捕获时状态供副本识别。成员移出后不再套用其配置，新加入成员尚未捕获的 INI 明确显示为共享配置；更新配置范围必须使用显式捕获操作，不能把当前其它活动方案的参数自动写进被编辑方案。

```ts
interface PlannedPresetExtensions {
  mode?: 'states' | 'profile';
  profileRef?: { revision: string };
}
interface PlannedProfileManifest {
  version: 1;
  gameId: GameId;
  root: string;
  presetId: string;
  revision: string;
  name: string;
  members: Record<string, boolean>;
  files: {
    modId: string;
    relativePath: string;
    sourceRevision: string;
    sha256: string;
    blob: string; // 主进程生成的配置存储引用
  }[];
}
```

配置资料存于 userData/profiles/<game>/<presetId>/<revision>/，保存 Mod 内 INI 的原始字节及完整 manifest。revision 文件不可原地改写，新保存创建新修订，准备完成后原子更新预设引用；取消或失败不更新引用。manifest 同时记录成员、名称和原根，保留旧修订的可识别归属。

INI 每文件沿用 4 MiB 限制，首版配置捕获预算为最多 2048 个文件／64 MiB；超限明确拒绝，不静默遗漏文件。捕获范围由页面列出并让用户确认，既可覆盖方案成员的全部可管理 INI，也可显式选择需要隔离的文件；未选择的配置显示为共享配置。

活动方案引用写在当前库可选 activeProfile 中，包含 presetId、revision 和最后应用的内容修订／文件摘要。变更检查由实际字节及成员启停状态共同得出，不把持久化标记当成唯一事实。成员启停变化利用库刷新核对；相关文件仅在预设页打开、切换、INI 保存／恢复和明确刷新时读取，避免每次搜索扫描所有配置。

### 3.4 备份、恢复与隐私

完整快照增加当前游戏配置档案及其引用；复制完成再发布备份记录。恢复前验证 manifest、字节摘要、身份、原根和路径，不能只恢复引用而缺少对应字节。

旧快照没有 profiles 时仍可恢复，按旧数据默认值读取，活动方案不伪造为已应用。另一游戏资料保持。配置删除仅移除方案引用并保留受控资料，空间回收由第二批 F04 提供。

单 Mod 换包／内容恢复保持当前收藏和标签；恢复已移除项时可取副本中的值。完整库快照恢复则按快照还原收藏和标签。依赖声明、内容修订与文件级绑定按对应内容版本恢复，并重新核对启用规则。

日志只记录操作、ID、数量、结果和关联副本；配置正文、依赖备注、Cookie、来源 URL 和绝对路径不进入日志。

## 4. 功能模块：F05 独立配置方案

### 4.1 创建、复制与保存

1. 在预设页选择“创建配置方案”，确认名称、成员及 INI 范围。
2. 主进程按当前根解析每个 Mod，拒绝链接和越界路径，读取原始 INI 字节与摘要；验证内容修订在捕获期间未变化。
3. 准备完整修订目录与 manifest，再更新预设引用；热键随对应 INI 保存，不二次改写编码或换行。
4. 复制方案生成新身份并保留独立引用；原档案后续修改不会改写副本。
5. 活动方案内修改／恢复 INI 后显示“有未保存配置改动”。保存配置生成新 revision，更新活动引用；收藏和标签改变不触发配置未保存状态。

原有“从当前状态创建预设”和“保存当前状态”继续是启停操作，不能默默覆盖 INI 快照。配置档案提供单独的保存配置按钮。

应用纯启停预设只改成员状态，活动配置档案的 INI 引用保持，并显示启停已偏离保存值。删除活动档案需明确确认，移除引用及活动标记而保留当前 Mod 字节；无活动档案时首次应用配置方案仍保存操作前参数副本。

### 4.2 切换流程

1. 当前活动方案有未保存的已落盘配置时，提供“保存后切换／保留恢复副本后切换／取消”。编辑器尚未提交的文本先由页面完成保存或取消，主进程不宣称能够读取渲染层草稿。
2. 读取目标档案，计算成员启停及所选 INI 变更，检查缺失成员、contentRevision、旧文件摘要、父目录阻挡、F06 依赖及既有互斥选择。
3. 缺失配置目标或内容修订不符时阻止套用，列出需修复项；仅缺失的启停成员沿用现有逐项说明。版本变化后必须重新捕获或人工适配，不能直接覆盖新版完整 INI。
4. 用户完成必要选择后，服务重新核对预览标识、根、档案修订与实际文件，准备全量前后字节及恢复记录。
5. 提交配置与启停，最后更新 activeProfile。预设外成员及未捕获文件保持实际状态；显示真实结果并刷新主窗／浮窗。

### 4.3 中断恢复

引入 version:2、purpose=profile-switch 的受控记录格式：文件步骤只处理已解析 Mod 内的 INI；目录步骤只处理成员的启停改名；元数据只处理固定游戏库、预设及方案引用。文件目标必须能由备份中的 Mod 身份／相对目录和 INI 相对路径重新推导，禁止仅凭记录中的绝对路径写入。旧 version:1 操作记录继续可读，普通操作的原预算和权限边界保持。

配置切换准备阶段先保存所有前后字节、摘要和目录身份。文件写入后再进行有依赖顺序的启停，回退按反序恢复目录再恢复原 INI；操作记录必须能解释文件在目录改名后的当前位置。不得给任意绝对文件提供通用写入权限。

这是一项配置切换内部的恢复单元：全部准备成功后提交，失败时回退本次变更，只有全部完成才切换活动标记。外部修改导致不能安全回退时保留副本及记录，暂停受影响根并由现有“备份与恢复”处理；不得把部分套用显示成新方案已激活。普通批量管理仍沿用逐项提交。

新记录按最多 5000 个成员、2048 个 INI／64 MiB 设置预算；记录序列化大小另设上限，所有预算在修改文件前检查。须验证复制、文件替换、目录改名、元数据提交及回退过程中的磁盘不足、占用和真实测试进程退出。

## 5. 功能模块：F06 依赖与兼容声明

### 5.1 版本来源与可信含义

新增 InstalledVersions 服务，读取所选安装根内 Resources/Packages/Launcher、Resources/Packages/XXMI 及该游戏的 Resources/Packages/ZZMI 或 EFMI 下的 Manifest.json 等已确认的本地版本资料。当前 deployment.ts 按 releases.ts 的 source.id 写入这些 Manifest；已有安装缺失、格式异常或不能对应组件时返回 unknown，不读取远程最新发行号来冒充已安装版本。

首版比较可规范化的数字版本及可识别的 v 前缀；自定义文本和无法可靠比较的预发行号显示未知。Mod 版本比较使用现有来源／人工记录，并标明“按记录版本判断”。本地包声明的版本与官方签名校验、游戏实机兼容分别说明。

这部分最小读取能力在第一批完成，F03 第二批再汇总运行库、路径、完整诊断及报告导出。第一批不因 F03 页面尚未开发而遗漏最低版本检查。

### 5.2 检查与选择策略

| 情况 | 首版行为 |
| --- | --- |
| 前置 Mod 缺失或计划执行后处于停用 | 阻止启用依赖方，提示选择前置；只有用户明确选择联动启用才把它加入操作 |
| 已知组件／前置版本低于最低要求 | 阻止本次启用，显示当前记录版本和要求 |
| 版本不可读取／不可比较或只有游戏兼容声明文本 | 显示未知与声明来源，允许用户在本次确认中明确接受未知，人工验证状态仍保持原值 |
| 停用／移除前置将破坏已启用依赖方 | 显示受影响项，选择取消或明确一起停用依赖方，不静默连带改变 |
| 依赖与互斥规则同时存在 | 先计算目标状态，再让用户解决互斥选择；不能借依赖联动绕过既有互斥规则 |
| 循环、自依赖、跨游戏／根引用 | 保存或执行前拒绝，原数据保持 |

按拟执行后的完整状态检查，不能只检查当前已启用集合。启用时前置先于依赖方，停用时依赖方先于前置；批量中某项失败后，未执行依赖方重新检查并单独报告。

规则覆盖主窗、浮窗、批量、旧预设、配置档案、移除、内容换包和恢复。保存新的声明若会立即破坏已启用状态，先要求用户停用或解决前置，再保存。

检查结果和用户接受未知的选择形成主进程短期 planToken，固定根、动作、身份、内容修订、版本及状态摘要。确认时重新校验；不提供永久“忽略所有依赖”开关，也不把未确认的查询结果当作执行授权。

## 6. 功能模块：F08 来源检查与手动换包

### 6.1 检查范围与结果

首版对有可靠 GameBanana modId/fileId 绑定的 Mod 提供“检查来源更新”，支持用户手动检查单项或所选项。没有可靠绑定时仅展示既有来源链接及手动换包入口，不凭同名猜测身份。

用户编辑的来源链接与现有站点绑定不一致时，显示绑定分歧并要求核对来源；不能自动改绑或把另一条目的文件当作目标升级。站点绑定所属游戏、查询条目和下载文件在检查、选择及提交时分别复核。

通过现有共享 browserSession.fetch 查询受控 Mod 详情，复用当前 _sVersion、_aFiles 解析及游戏验证；相同站点 Mod 合并请求，检查最多并发 3 项，默认不启动后台轮询。缓存结果带 checkedAt 和根／内容修订，网络、权限和字段变化返回逐项错误，不清除当前安装记录。

| 站点信息 | 页面结果 |
| --- | --- |
| 作者声明版本可比较且高于已记录版本 | “来源声明版本较新”，列出可选文件，仍需用户选择变体 |
| 原 fileId 的大小／摘要发生变化 | “原文件发生变化”，不能自动当作更高版本 |
| 有其它 fileId，但无法可靠判断替代关系 | “有可选文件／需人工确认”，不按最大 ID 或最新时间直接挑包 |
| 版本相同且绑定文件信息一致 | 显示本次检查未发现可确认变化 |
| 缺少字段、多变体、无版本或来源不可访问 | 显示未知、选择要求或具体访问问题 |

站点 Mod 的版本声明不等于每个文件都是同一变体的最新包。新下载仍验证游戏、文件身份、大小和摘要；字段兼容性在真实联调阶段确认，不因受控样本通过宣称网站契约稳定。

### 6.2 下载与更新任务

用户选择文件并确认下载后，复用下载服务、取消／重试和完整包缓存。任务新增目的 new-install/update；更新任务固定 targetModId、gameId、targetRoot 和 expectedContentRevision。

任务记录持久化，重启不自动下载或替换。页面区分“安装新 Mod”与“替换已安装 Mod”，更新任务绝不能误走普通新导入分支；根变化或目标已经换包时原计划失效，保留压缩包并要求重新规划。

### 6.3 确认替换与配置保护

1. 校验完整包并解包预备，选择与目标对应的包内条目。多 Mod／多变体包必须明确选择，首版一次替换一个已安装身份，其余内容留在缓存。
2. 显示当前与来源声明版本、目标目录、受影响 INI、当前活动档案、旧版恢复副本及依赖问题；用户明确确认后进入文件队列。
3. 原 Mod 内容及完整记录、活动配置引用先留恢复副本。保持 ID、名称、角色／分类目录、用户元数据、自选封面、收藏和标签；更新 remote、provenance 历史及 contentRevision，人工验证状态重置为 unverified。
4. 用户配置与新版默认 INI 分开显示。首版不自动用旧完整 INI 覆盖新包；提供保留旧配置资料、使用新版默认或在受控暂存中人工适配的选择，适配后再复核依赖及目标摘要。
5. 原停用项继续停用；原启用项只有在本次确认与规则校验完成后保持启用。依赖不满足或需重新选择时先处理确认，不能静默改变依赖方或启用新导入项。
6. 沿用单 Mod 内容提交，连同库记录、预设／活动档案引用一起保存。更新完成刷新主窗和浮窗，报告原身份已换包，不新增第二个 Mod ID。

若原 Mod 位于活动配置档案中，用户对新配置的选择作为该成员的新快照修订提交；其它档案中引用旧 contentRevision 的配置标为“需重新适配”，保留旧字节但禁止直接套用。更新回退恢复对应旧内容、绑定和档案引用，重新核对当前依赖／互斥状态。

文件准备或提交失败时保留下载包与可恢复副本。日志、任务、库和方案引用均报告实际结果；取消确认不会写 Mod，替换过程中退出走既有队列与中断处理。

## 7. 功能模块：F09 收藏与 F10 标签

### 7.1 页面与操作

收藏按钮放在列表行独立操作区域和详情页，不能嵌套进现有 Mod 行按钮。提供“全部／收藏”筛选，角色概览进入的范围与收藏筛选取交集。写入成功后刷新状态，失败保留原标记并显示错误。

标签在详情独立编辑区域维护多个值，提供已有标签建议、添加／移除和保存；库增加标签筛选，首版多标签采用同时满足（AND），与搜索、角色、分类、启停及收藏共同生效。搜索索引包含标签，仍在库变化时更新。

列表仅展示少量标签及更多数量提示，详情显示完整内容，保持既有虚拟行高度。收藏写入不能覆盖未保存的标签／作者／版本草稿，切换身份时清理旧对象草稿；外部刷新按现有草稿合并原则处理。

### 7.2 身份与恢复规则

改名、分类移动、启停、普通替换及站点换包不改变收藏／标签。依赖和版本记录使用同一 Mod ID，预设不另存一份收藏／标签，方案切换也不改这些个人整理信息。

已有库缺少字段时正常显示默认值；非法新字段明确拒绝并保留文件。单项内容恢复与完整快照恢复按第 3.4 节的不同语义执行，测试中必须分别覆盖。

## 8. 对应接口与兼容

下表为拟接口，不是当前 API 清单。实现时在 shared/contracts.ts、ipc-contracts.ts、preload/index.ts、main/index.ts 同步注册，并更新权威文档与 AST 清单；IPC 仍只允许受信任主窗／浮窗，远程网页没有管理器桥接。

| 拟方法／扩展 | 输入与返回 | 主要规则 |
| --- | --- | --- |
| 扩展 operateMod | favorite/tags/requirements 操作；仍返回 LibrarySnapshot；可选确认参数 | 不把新字段塞入现有 metadata 表单的完整替换；写入进入主队列 |
| dependencyCheck | game + ActionRequest → DependencyPlan | 动作可描述启停、批量、预设、声明保存、移除或换包；返回 issues、必要联动选择、planToken；纯检查不修改库 |
| profileCapture | game + presetId／新名称 + INI 范围 → Preset[] | 捕获当前真实内容，原子更新配置修订 |
| profileDuplicate | game + presetId + name → Preset[] | 新方案 ID，不改原方案 |
| profileStatus | game + presetId → ProfileStatus | 活动／未保存／内容修订不符／缺失信息，按需检查相关配置 |
| profilePrepareApply | game + presetId → ProfileApplyPlan | 返回文件范围、阻挡及未保存改动处理；不是 F02 通用预设预览的提前交付 |
| profileApply | game + planToken + 用户选择 → ProfileApplyResult | 重新校验后提交；返回真实库、活动引用、问题和恢复项 |
| readProfileIni | game + presetId + revision + modId + relativePath → IniDocument | 仅对应受控档案配置，拒绝绝对路径；大文件沿用既有上限 |
| checkModUpdates | game + modIds → 逐项检查结果 | 所有站点请求、Cookie 和缓存留在主进程，禁止任意 URL |
| prepareModUpdate | game + targetModId + candidateId → 下载任务状态 | candidateId 为本次主进程检查返回的受控选择，重新绑定后才启动确认下载 |
| 扩展下载安装计划／任务操作 | purpose、targetModId、expectedContentRevision 和 UpdatePlan | 下载页面处理明确的换包计划；开始、重试、目录变化和最终提交均校验目标 |
| 扩展既有启停／批量／预设／恢复入口 | 可选 planToken 与本次未知项确认 | 老调用继续可用；主进程始终检查，新必需选择未确认时不执行，不留旁路 |

ActionRequest 只能描述支持的业务动作和身份，文件路径由服务生成。计划令牌短期有效、同一上下文使用，状态变化后需重读。Result 的错误说明及拟结果 DTO 必须让页面展示依赖和配置问题，不能只吞成一条通用成功提示。

拟对 Result 的失败端增加可选 code 和受控 details，区分计划失效、依赖需选择、配置修订不符等；旧消费者仍可读取 error，新页面可据结构化结果重新规划。主进程检查不能因旧调用没有令牌而跳过：无需选择时直接执行，需要确认时返回明确失败／问题，等待对应流程补齐选择。

查询保持响应，所有写入和确认后的执行进入既有 mutation 队列。管理器更新安装、Mod 换包、配置切换和退出协调同一写入边界；来源查询或下载等待期间不能占住文件队列。

## 9. 显示界面与完整用户流程

| 页面 | 第一批新增内容 |
| --- | --- |
| Mod 库／详情 | 收藏按钮及筛选、标签编辑／搜索／筛选、依赖声明和问题、检查来源更新 |
| 预设 | 启停预设／配置方案的明确类型、配置范围、复制／捕获／保存、活动和未保存状态、切换确认 |
| 下载进度 | 普通安装／更新任务的目的、固定目标、版本和配置影响、确认替换及旧版副本入口 |
| 备份与恢复 | 配置切换中断记录、内容换包的配置引用及旧版恢复范围 |
| 浮窗 | 新依赖检查及必要确认，沿用共享启停规则；收藏／标签的完整编辑仍在主窗 |

典型验收流程：为 Mod 收藏并设置标签 → 声明前置 → 建“日常”和“拍照”两个配置方案 → 分别修改参数／热键并保存 → 切换验证实际文件 → 检查来源并选择新包 → 在下载页确认配置处理和换包 → 查看旧版副本 → 恢复后验证身份、个人整理信息及方案关联。

## 10. 实施步骤与文件落点

批内顺序按共享依赖安排，不改变五项都属第一批高优先级的决定。

1. **数据与兼容基础**：库可选字段、contentRevision、预设档案引用、配置存储和备份扩展；确定旧库／旧快照恢复策略。新增共享 DTO 仅在编码阶段落地。
2. **F09／F10**：ModService 校验与写入、详情和筛选、草稿保持及虚拟行；以简单功能验证新字段在替换／恢复中不会丢失。
3. **F06**：新增 src/main/mod-requirements.ts、installed-versions.ts，统一拟状态检查与计划确认，接入所有启停及内容操作入口。
4. **F05**：新增 src/main/profiles.ts，扩展 BusinessService／IniService／FileOperations，先验证文件与中断恢复，再接预设页面。
5. **F08**：新增 src/main/mod-updates.ts，复用站点解析与共享会话；先完成候选分类和固定目标任务，再接换包／配置重建和下载页面。
6. **交叉回归与资料**：核对配置、依赖、换包、个人字段和恢复的一致性；维护日志、API、版本说明及分层证据。

## 11. 验收矩阵

| 范围 | 必须通过的检查 |
| --- | --- |
| 旧数据 | 缺少新字段的库／预设／任务／快照可读，读取不把旧预设默认为配置档案；错误数据不被覆盖 |
| F09／F10 | 字段校验、Unicode 去重、组合筛选、离屏选择、收藏失败回退、未保存标签／作者草稿、重启及两游戏隔离 |
| 身份与恢复 | 改名、分类、启停、换包不丢个人字段；单项恢复保持当前收藏／标签，完整快照按保存值还原 |
| F06 | 前置缺失／停用、版本低／未知、循环、反向依赖、互斥冲突；主窗／浮窗／批量／旧预设／配置方案／移除／换包／恢复一致 |
| F05 | 参数及热键实际隔离、原编码／BOM／换行、选择范围、复制互不覆盖、外部编辑及摘要冲突、内容修订不符拒绝套用 |
| 配置故障 | 准备、INI 写入、目录改名、活动引用提交和回退各阶段模拟空间／占用并强退自己的测试进程；原数据、恢复副本及标记一致 |
| F08 来源 | 两游戏身份、同版本原文件变化、多变体、无版本、私有／失效来源、超时和字段缺失；不按 fileId／时间猜最新包 |
| F08 换包 | 包校验、单条目选择、取消、重试、根变化、目标已换包、默认配置／人工适配；不新增身份，旧绑定只在提交成功后替换 |
| 方案与换包 | 活动方案重建对应配置修订，其它旧档案标需适配；恢复旧内容及引用后仍满足当前依赖／互斥 |
| 整体回归 | 批量、互斥组、预设、浮窗、INI、来源历史、共享浏览器／Cookie、下载、中断恢复、日志、设置和管理器更新协调 |
| 性能 | 同一千项库复测扫描、搜索、封面和预设流程；配置检查只读相关文件，不因新功能恢复逐成员全库扫描 |

类型检查、完整测试、API 清单与构建是源码门槛；实际 Electron 窗口另验证文件、列表、未保存草稿、确认、失败反馈和重启。真实 GameBanana 检查／下载／换包要单独记录，两游戏分别有证据；受控接口样本不能代替真实站点联调。

真实游戏、最新便携包、Release 下载／更新和用户人工体验继续按总规划独立安排。方案完成后应先交付源码及可复核结果，完成项再从待办总表移出并写入进度文档。

## 12. 外部契约与实施前核对

本地组件资料以当前部署／同步代码和 [XXMI Launcher 官方项目](https://github.com/SpectrumQT/XXMI-Launcher)为核对入口。最低版本读取必须关联当前安装根和组件，不根据远程最新版本推断。

站点公开入口见 [GameBanana API](https://api.gamebanana.com/)。现项目使用的 v11 字段以 gamebanana.ts 的解析与既有真实下载证据为基础；本次公开入口查询不能证明全部 v11 更新字段稳定可用。开发时先采集两游戏脱敏响应，验证 _sVersion／_aFiles、文件选择及变体含义，再确定缺失字段降级；无法可靠判断则交给用户选择，不承诺自动识别所有最新版本。

第一批最低版本检查、配置提交记录扩展和指定目标换包都是必需连接工作；第二批和第三批的完整产品功能不因这些连接点被提前标记完成。
