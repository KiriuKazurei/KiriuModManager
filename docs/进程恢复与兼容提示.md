# 进程恢复与兼容提示

2026-10-15；产品保持 0.0.5，开发 SDK 0.2.0。用户最新范围为进程重启和恢复，以及根据有效记录显示用户提示；不做游戏窗口获取、输入、Mod 加载效果、刷新和固定场景。实现分支为 `agent/process-recovery-compatibility`，开发起点为本地 agent/main 的 12beff7；开始时 GitHub 不可达。本次交付目标为回流并推送 `agent/main`，保留功能分支，实际提交与推送状态以 Git 引用为准。

## 框架与模块

开发 SDK 使用固定生产 launchPlan 和标准 Launcher 参数，不允许配置任意命令。先通过现有 local 门禁、稳定上下文及待恢复记录检查，再进入 Windows 专属 Job Object。游戏/Launcher 已运行或同名身份不可确认则拒绝接管。先记专属 Job 意图，再将挂起创建的 Launcher 归入 Job、恢复线程；后代进程仅在该 Job 内观察和操作，处理 PID 复用由内核句柄及 IsProcessInJob 保证。

正常重启和异常退出恢复分别有正常启动对照；目标失败重试需新的成功对照和相同上下文。目标启动连续超时两次可判该进程范围失败；缺条件、取消、助手异常、恢复不完整或重试偶然通过都是 inconclusive。失败生成本地任务，成功不触发 Git/发布。每次启动最多等待 120 秒，要求本轮游戏连续存活两秒；不代表游戏场景就绪。

结束时终止整个专属 Job 并确认空集合，持久记录完成状态。SDK 被强杀会关闭助手输入，助手 finally 关闭 kill-on-close Job；显式 recover 通过记录中的随机 Job 名收尾，绝不按游戏名称杀进程。遗留 execution 锁只在显式恢复且原 PID 已消失时清理；仍存活、PID 复用或权限不明时保持阻挡。watch 锁不自动清理；需核对具体无主记录后处理。记录损坏不自动删除。

SDK 不直接修改游戏、XXMI 配置或日常 Mod 文件；真实程序运行本身仍可能写设置和日志。它不提供自动重开用户原本就运行的游戏，也不接管其它进程。任何脱离 Job 的游戏进程无法取得本轮通过证据。

## 记录、对应接口和界面

| 接口 / 命令 | 对应功能 |
| --- | --- |
| `run --suite process --allow-processes` | 精确源码/本地接入门禁、两项进程验证、收尾、上下文复核、生成本轮报告及脱敏记录 |
| `watch --suite process --allow-processes [--game ...]` | 轮询稳定构建，按机器/源码/游戏/组件上下文去重；通过安静，失败本地记录；不后台安装服务 |
| `recover --process-journal ...` | 显式恢复记录中的专属 Job；幂等更新完成状态 |
| `compatibilityStatus(game)` | 只读核对已保存路径和本地记录；返回当前适用性，不能启动进程 |
| `importCompatibilityEvidence(game)` | 主窗口原生 JSON 选择器；校验游戏/范围/结果/摘要后原子保存，取消 null |

产品入口为设置→常规设置→进程兼容测试。CompatibilityPanel 使用 game key 隔离，在可见、焦点返回或设置改变时核对；hidden 不触发新读取，过期请求不覆盖当前状态。用户可手动检查和导入；原生选择取消后重新核对。读取失败会撤下原“通过”状态。

状态为 unverified（没有记录）、passed/failed/inconclusive（当前范围记录）、stale（环境/管理器不同）、unknown（读取或匹配不可靠）。记录按 `userData/compatibility/{game}.json` 保存，不改库、预设、人工 verification 或启停状态。主窗之外的调用拒绝。

目标指纹覆盖游戏 EXE、根下已知 config.ini/manifest.json/version.json/verify_files.json 的内容或缺失状态、Launcher/XXMI/importer Manifest、Launcher EXE、d3dx.ini、Importer Core 及已知 DLL/用户 INI、管理器 dist/main 编译代码、平台和架构。有界流式摘要检查读前/读后身份；配置或组件缺失时显示 unknown。它不是游戏语义版本，不覆盖全部游戏资源或所有运行环境因素。

导出的 compatibility.json 不含路径或原配置。SHA256 只提供完整性，不提供来源认证；产品明确标注用户本地导入。当前不联网拉取兼容结论，也不将进程结果升级为所有 Mod 的兼容承诺。完整游戏 verdict 保持 inconclusive。

## 验证与交付边界

源码门禁包括产品/SDK 类型、完整测试、99+1 API 检查、构建、路径修复窗口专项，以及新兼容提示窗口专项。新增测试实际运行 Windows 子进程树、正常重启、异常退出、SDK 强杀、专属树清理、无关进程保留、旧锁恢复和幂等恢复；结论策略覆盖重复失败、缺对照和波动。

`smoke:compatibility:process` 会编译自有 Launcher/游戏替身，分别运行两游戏真实 CLI 流程，再由实际 Electron 页面导入生成记录。受控窗口另外覆盖取消、错误游戏、过期、证据不足、重启持久化、浮窗权限。最终结果路径在完成进度中登记；失败报告保留，不改写为成功。

真实游戏与 XXMI 尚未运行。终末地已提供目录仍缺标准 Launcher；绝区零未提供测试安装。用户实际游戏验收、打包和 Release 保持独立安排。

内核 Job 查询与终止权限按 [Microsoft Job Object 权限说明](https://learn.microsoft.com/en-us/windows/win32/procthread/job-object-security-and-access-rights)使用 QUERY|TERMINATE；已另外覆盖仍存活 Job 的显式恢复路径。
