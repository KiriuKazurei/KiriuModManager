# 项目技术说明

更新日期：2026-10-14。当前源码版本 0.0.4，包含性能/中断恢复、本地日志及第一、第二批重点功能，为 Electron + React + TypeScript 本地 Windows Mod 管理器，支持 `zzz/ZZMI` 与 `endfield/EFMI`，不依赖 HTTP 产品后端。原页面/布局分工保留；用户已明确授权重点迭代和寻找 Mod 的完整页面接入，既有 GUI 工作保持。

## 架构与框架

React 主窗与浮窗通过 `window.kmm` 调用 typed preload；主进程验证窗口、可信文档 URL 和 main frame，再交给本地服务。当前为 80 个异步方法和 1 个可解除订阅事件，见[权威接口文档](桌面接口文档.md)。type-only IPCContracts 在构建时约束参数/结果，sandbox preload 编译后仅 require Electron。内置远程网页使用独立 WebContentsView/Session，无 preload/本地接口；market 接口仅可信主窗口可用。

| 框架 | 当前落点与职责 |
| --- | --- |
| F1 桌面宿主 | `main/index.ts`：主/浮窗、托盘、关闭/恢复/退出、同 profile 单实例与独立 profile |
| F2 应用外壳 | renderer + Vite/TS：真实 React 页面、导航与游戏选择；源码构建入口已具备，视觉由 Cursor 维护 |
| F3 契约与桥接 | `shared/contracts.ts`、`shared/ipc-contracts.ts`、preload：Result、typed invoke/handle、来源边界、事件解订阅 |
| F4 配置上下文 | `settings.ts`：两游戏路径/偏好/选择持久化；原子 selectGame、新增局部 patch 与兼容全量保存 |
| F5 文件归档 | `archive.ts/mod-archive.ts/mods.ts/recovery.ts`：普通目录边界、复制、ZIP/7z/RAR、同名拒绝与副本 |
| F6 数据资源 | 稳定 Mod ID、按游戏 metadata/图片引用、88 本地参考角色画像（57 + 31），来源/hash 见资产 manifest |
| F7 操作协调与运行时 | 主进程队列协调相关读取/变更/通知；固定 helper、完整 7z.exe/dll 与包脚本已具备，保留既有框架验收包 |

主队列涵盖配置、扫描/图片/INI/预设/恢复等关联操作；操作完成后按策略广播，再进入下个队列任务。进度 polling、桌面 status/show/quit、目录选择等响应入口不会被长部署阻塞。通知 gameId 是当前 selectedGame，settingsChanged 是配置重读提示；取消某些操作也可能刷新，结果看本次 Result。

## 本地数据

默认是 Electron userData；测试使用绝对 `KMM_DATA_DIR` 指向 `.run-data` 下自己的目录，不访问真实用户库。

| 相对数据路径 | 归属 |
| --- | --- |
| `settings.json` | version、selectedGame、两游戏 GamePaths、可选 desktop；store 临时写后 rename |
| `library-zzz.json/library-endfield.json` | 当前 root、稳定 records/metadata、groups、Mod/角色图引用 |
| `presets-<game>.json` | 当前 root 的预设和稳定 ID 成员 |
| `character-covers/<game>/` | 自定义角色图，与 Mod 根文件分开 |
| `removed/<game>/<id>` 与同级 `.json` | 实际恢复 payload 和范围/身份 sidecar，覆盖前副本也在这里 |
| `pending-operations/<id>.json` 与同名目录 | 目录提交阶段、身份与前后元数据；未完成项通过原恢复接口处理 |
| `logs/operations.jsonl` 与 `.1`–`.3` | 本地操作及备份/提交关联日志，单文件 2 MiB，不保存原始配置或 URL |
| 目标同盘 `DISABLED_.kmm-operation-<id>-<index>` | 受控暂存、原目录和回退后的新内容核对副本；管理器扫描排除 |
| `downloads/deploy-*` | 下载及验证 staging/cache；不是用户 Mod 库 |
| `mod-downloads/tasks.json` 与任务子目录 | 0.0.2 网站下载摘要和完整包缓存；中断任务重启后不自动续装 |
| XXMI 根 `.kmm-backups/paths-*` | 外部原 Launcher 配置/INI 副本，可能包含原 Secrets，应按原配置妥善保管 |

资源由 `assets/character-covers/manifest.json`、`assets/refresh-helper.ps1`、依赖 7zip-bin-full 的完整 Windows 7-Zip 提供。资产是本地参考资源，来源/hash 保留，未声称原创或已正式发布。

0.0.2 在线导入为每项在 root 的同磁盘受控暂存区准备完整内容，再提交停用目录与可选 remote 绑定；library JSON 和任务 JSON 原子替换，Windows 短暂占用有界重试。旧 version:1 无 remote 数据可读，替换/恢复/快照关联规则见[实现与验收](0.0.2寻找Mod实现与验收.md)。

## 源码命令与验收边界

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run api:inventory
npm.cmd run api:check
npm.cmd run build
$env:KMM_DATA_DIR = Join-Path $PWD '.run-data\manual'
npm.cmd start
```

`npm.cmd run dev` 编译 main/preload 并启动 Vite + Electron；`start` 使用已有 dist，需先 build。Node.js 22.12+，本机 Node 24。不要设置 `ELECTRON_RUN_AS_NODE` 启动 GUI。可选 KMM_DEBUG_PORT 仅本地验收。

功能窗口脚本：smoke、smoke:framework、smoke:deployment，以及 smoke:mods/business/gallery/desktop 的 `--functional`；局部接口用 `node scripts/smoke-settings-patches.mjs`，Mod/业务 bridge 用相应 smoke-*-interfaces.mjs。KMM_SMOKE_DIR 指向 `.run-data` 隔离证据，每次随机 run，原生选择器响应由特权 driver 注入，正式 bridge 不提供任意路径口。functional 保留业务/真实文件断言，只不验 CSS 尺寸/排版。

不在本轮运行 `verify:official` 联网验证、真实 XXMI 或游戏；部署使用隔离签名 HTTP fixtures。helper 自测只输入到自己确认的测试 App。新便携包/ZIP/packaged 门禁用户已取消（deferred-by-user），M14 既有打包能力及旧包保留，不把旧包称作本轮模块最终包。

## 0.0.4 第一批增量

`mod-library.ts` 统一标签和版本/声明校验；`dependencies.ts` 从所选安装的组件 Manifest 读取版本，维护绑定游戏、根、内容与状态的短期确认，统一操作最终状态检查与依赖排序。

`profiles.ts` 使用现有预设模式与不可变 INI 修订，实现捕获、复制、磁盘状态、预览及配置切换；`file-operations.ts` 在保留 v1 的同时扩展受限 v2 文件提交。配置切换先保存完整副本，再一次准备 INI、目录移动和索引；进程中断后由恢复页回退。外部 INI 修改使恢复不可靠时停止覆盖。

`mod-updates.ts` 通过内置浏览器的同一 Cookie Session 查询已绑定 Mod，提供来源版本/文件变化及明确候选；`mod-downloads.ts` 持久化定向更新用途、目标 ID/根/内容修订/候选指纹。下载页展示 INI 差异并选择单个包内条目，主进程确认后替换；新导入与定向更新使用独立路径，保持原启停和整理字段、原绑定/配置副本。

ModOrganizationPanel、ModUpdatesPanel、ProfilePanel 分别承载整理/依赖、更新查询和独立配置。收藏按钮在行选择按钮外，标签与既有筛选取交集；同身份局部更新保留草稿。INI 编辑器放弃草稿需确认。新增接口和分层验收见[0.0.4 说明](0.0.4版本说明与验收.md)，后续待办已清理完成的五项。

## 第二批 0.0.4 增量

新增只读任务／文件证据框架和无迁移扫描，服务包括 Diagnostics、RecoveryStorage、RestorePlanner、ConflictInspector。检查工作在后台有界执行，开始时固定游戏／路径；共享写队列继续协调实际恢复、清理、保护及导出。清理使用独立归属与阶段记录，不扩大 FileOperations 的路径白名单。

Settings 新增诊断页签；RecoveryPage、ConflictPage 替代旧页面分支；INI 编辑器支持摘要约束的 Mod 内文件／行定位；排序为共享纯函数、按游戏本地偏好和可选虚拟列表锚点保持，无新增排序 IPC。旧三项恢复／冲突接口保持兼容。

新增保护 sidecar、清理 manifest 及可选备份路径／大小清单；配置修订只盘点与保守保留引用。当前类型、预算、实际入口、151 项测试和性能时间差限制见[第二批功能与验收](0.0.4第二批功能与验收.md)。
