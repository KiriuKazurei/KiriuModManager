## 1. 目标与已确认需求

将原先预留的 Mod 商店入口改为指定网站浏览入口，让用户在管理器内完成“寻找 Mod → 下载 → 自动安装 → 查看绑定信息”。

| 已确认要求 | 本方案中的行为 |
| --- | --- |
| 左侧栏新增“寻找Mod” | 与“Mod 库”并列；点击进入独立页面 |
| 绝区零使用指定网页 | 固定首页为 https://gamebanana.com/games/19567 |
| 使用内置浏览器浏览 | 网页显示在主窗口内，提供后退、前进、刷新和返回游戏首页 |
| 使用内置下载服务 | 接管网页产生的受支持 Mod 下载，显示任务与进度 |
| 下载完成后自动安装 | 完成信息核对、包校验和导入，成功后刷新 Mod 库 |
| 绑定对应 Mod 信息 | 保存来源页面、站点 Mod/文件身份、作者、版本、简介和分类原文 |
| 绝区零 Mod 目录允许调整 | 继续通过“设置 → 路径设置 → Mod 目录”调整和保存；网站功能读取该配置，不另建安装目录设置 |

方案编制阶段按用户要求暂停后续功能实现；用户随后确认开发 0.0.2，已完成对应源码、页面与分层验收，实际完成情况见第 10 节。

## 2. 首版范围与默认决策

以下首版规则已作为 0.0.2 的实施依据；具体落地行为及验收边界以实现记录说明。

| 事项 | 首版规则 |
| --- | --- |
| 支持游戏 | 接入绝区零；终末地显示“尚未指定 Mod 网页”，不猜测网站或安装到绝区零目录 |
| 网站形态 | 显示原网站，使用网站现有搜索、分类和详情页；不制作自建商店或后台 |
| 下载来源 | 自动安装 GameBanana 托管并能唯一绑定到详情记录的文件；外部网盘、作者赞助页等链接由用户点击后交给默认浏览器，下载后可走已有本地导入 |
| 下载格式 | ZIP、7z、RAR；拒绝把 EXE、安装器、脚本、图片或普通网页作为 Mod 自动安装 |
| 安装后启停 | 建议默认停用，并在任务中显示“安装完成，尚未启用”；用户在 Mod 库启用时遵守现有互斥组规则 |
| 同名冲突 | 保留现有内容，报告具体冲突；用户可改名或使用已有带恢复副本的替换功能，不自动覆盖 |
| 异名重复 | 首版不增加全库内容指纹；同一站点文件已经绑定到当前库时提示已安装并避免重复自动导入 |
| 登录 | 保留独立浏览会话中的网站 Cookie；登录在网站页面进行，不把账号或密码保存到管理器业务设置，不新增账号系统 |
| 下载调度 | 最多 3 个进行中的下载；达到上限时说明原因，不启动无上限下载；安装文件操作依次执行 |
| 重试与断点 | 支持明确的失败后重新下载、重读绑定信息及使用完整缓存包重试安装；首版不承诺网络断点续传 |
| 重启恢复 | 保存任务摘要与完整下载包位置；重启后保留完成/失败记录，未完成任务标为“已中断”；不在启动时自动续装 |
| 缓存清理 | 首版保留完整下载包供查看和重试，不自动删除用户的 Mod、已有副本或缓存；自动清理策略另行规划 |

“自动安装”不等同于自动启用或自动启动游戏。默认停用可避免下载一个新外观时立即与现有外观同时加载，也不会根据角色名称自动创建互斥组。

## 3. 使用流程与目录调整

### 3.1 常规流程

1. 用户选择绝区零，进入“寻找Mod”。
2. 页面显示 GameBanana 首页、浏览工具栏、当前安装目录及下载任务区。
3. 用户通过网页搜索或分类打开具体 Mod 详情，选择该页面的下载文件。
4. 主进程建立任务，记住当前游戏和已保存的 Mod 目录，读取对应站点信息，确认文件属于绝区零并与所点击文件唯一对应。
5. 内置服务下载到管理器缓存；任务显示文件名、作者/名称、字节进度、目标目录，可取消尚未开始安装的任务。
6. 下载完成后核对大小；网站提供校验值时核对校验值，然后使用已有安全解包和 Mod 识别能力处理压缩包。
7. 检查当前目录配置和同名冲突，将可安装项导入为停用状态，同时保存稳定 ID、来源信息和站点绑定。
8. 任务显示成功数量及逐项失败原因，主窗口和浮窗收到库变化通知。
9. 用户点击“查看已安装 Mod”进入对应库；必要时选择互斥组成员并启用。仅完成文件导入不宣称游戏兼容性已验证。

```mermaid
flowchart LR
    A[寻找Mod] --> B[网站详情页]
    B --> C[用户点击下载]
    C --> D[核对游戏、文件与保存目录]
    D --> E[内置下载与校验]
    E --> F[安全解包与识别]
    F --> G[检查目录与冲突]
    G --> H[安装并绑定信息]
    H --> I[显示结果并刷新库]
    I --> J[用户按互斥规则启用]
```

### 3.2 设置里的目录是唯一来源

- 本轮继续复用 `Settings.games.zzz.modsDirectory` 和 `saveGamePaths`。用户编辑后必须保存，未保存草稿不改变安装位置。
- 新任务读取最新已保存目录；用户更改目录后开始的新下载使用新目录。
- 每个任务保存自己的 `gameId` 和 `targetRoot`。切换到终末地或离开“寻找Mod”不会把任务改装到另一游戏，也不会取消正常下载。
- 安装进入文件队列后再次读取最新配置。若目录与任务开始时不同，进入“等待选择目录”状态，保留完整包，暂不写入旧目录或新目录。
- 任务提供“按当前目录安装”操作，明确展示原目录和当前目录。用户确认后更新该任务目标，再入队复核；若再次改变，继续等待，不静默追随设置。
- 目录为空、不存在、不可写、为磁盘根目录，或包含现有导入器拒绝的链接/联接时不自动安装，给出“前往设置”与可用的重试操作。
- 更改设置只改变后续管理范围，不自动搬迁旧目录中的 Mod；旧文件保留。继续沿用当前库按游戏和目录关联的规则，本轮不扩展为多库档案或自动迁移向导。
- Mod 目录不在所选 loader 读取范围时显示现有路径警告，并提供设置入口；不要在安装时擅自改写 XXMI 配置。

## 4. 底层框架与模块划分

现有桌面架构为 Electron 主进程 + React 管理器页面 + sandbox preload/typed IPC；Mod 导入、恢复副本、稳定 ID、来源/版本记录和互斥规则继续复用。

| 层级/模块 | 职责 | 实现边界 |
| --- | --- | --- |
| 浏览器宿主 | 创建独立 WebContentsView；布局、导航、网页错误、关闭释放 | 无管理器 preload；远程页面不能访问 `window.kmm` 或本地业务接口 |
| 网站适配 | 解析详情身份，调用官方数据接口，核对游戏和文件，转换元数据 | 以站点响应核对下载，不只根据标题、文件名或当前选中的游戏猜测 |
| 下载服务 | 捕获浏览器下载，分配缓存文件，控制进度/取消/上限，保存任务 | 不复用管理器更新器的安装动作；二者共享应用生命周期协调即可 |
| 自动安装协调 | 完整包校验、解包、Mod 识别、目录复核、逐项提交、结果通知 | 下载不占据全局文件队列；安装阶段进入现有队列，避免与启停、替换、恢复争抢文件 |
| Mod 服务 | 新 Mod 的稳定 ID、停用目录、元数据和来源绑定持久化 | 文件与对应信息一起提交，不在导入成功后靠 renderer 补写绑定 |
| 设置模块 | 保存每游戏 Mod 目录；为新任务和安装复核提供最新配置 | 保留当前局部保存与未提交草稿处理，不新增第二套路径来源 |
| React 页面 | 导航、浏览工具栏、目录说明、下载任务、结果跳转 | 延用当前视觉风格；不重做现有 Mod 库和设置页 |

浏览页面使用 Electron 官方 [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)；下载接管使用独立 Session 的 `will-download` 和 [DownloadItem](https://www.electronjs.org/docs/latest/api/download-item)。网页会话与管理器本地页面、XXMI 下载和管理器更新会话隔离。

### 4.1 网页和桌面权限

- 管理器页面保持现有 IPC 发送者、主 frame 和本地文档地址校验。新的浏览器接口只向可信主窗口开放，浮窗不控制内置网页。
- 远程视图使用 sandbox、context isolation、禁用 Node 集成，不注入管理器桌面桥接；拒绝网站的摄像头、麦克风、文件系统等桌面权限请求。
- 顶层站内导航限定 GameBanana 的 HTTPS 网站地址；下载允许经核对的托管文件域名和重定向链。白名单以实际响应核实，不允许任意 URL 转换为自动安装任务。
- `target=_blank` 的站内链接在同一内置视图打开；外站 HTTPS 链接在确认为用户点击后交给默认浏览器。脚本弹窗、危险协议、本地文件和带凭据 URL 不自动打开。
- 子资源保留网站正常所需网络访问，不把网站主页面改写成自制页面，也不绕过网站登录或访问限制。
- 切换页面时移除/隐藏原生视图；窗口缩放、侧栏折叠/拖动、页面滚动及 DPI 改变后重新同步区域。原生网页不能挡住导航、任务按钮或管理器弹窗。

### 4.2 下载与安装的安全边界

- 首版沿用现有解包上限：最多 50,000 个条目、解压后最多 2 GiB；在线下载包也限制为 2 GiB。
- 拒绝路径穿越、绝对路径、链接、特殊文件、重复目标路径；网站/压缩包给出的文件名不能决定任意磁盘目标。
- 校验大小，核对网站提供的校验值。MD5 只用于与站点文件记录比较，不作为作者数字签名或安全/兼容性证明。
- 网站未提供校验值时显示“已核对大小，网站未提供摘要”，继续执行安全解包；不能显示已完成不存在的摘要验证。
- 未找到包含 INI 的 Mod、需要密码、包损坏或格式不支持时不自动安装，保留可用完整包及具体错误。包内文件不会被作为 EXE/脚本自动执行。
- 对每个候选 Mod 先检查目标，再在受控暂存目录准备完整内容，最终提交到目标；只处理本任务创建的目录。信息保存失败时撤回本项新内容或明确报告待恢复位置，避免未绑定的残缺目录直接进入正常库。
- 多 Mod 包允许逐项成功与失败并存，后续候选不因一个同名项被悄悄跳过；成功 ID 和失败原因同时显示。此措施针对导入提交，不扩展为整个应用的全局事务系统。

## 5. Mod 信息绑定与数据结构

### 5.1 信息映射

| 信息 | 来源与保存规则 | 页面位置 |
| --- | --- | --- |
| 稳定 Mod ID | 管理器为每个导入项生成；一个包有多个 Mod 时各有自己的 ID | 现有库内部关联 |
| 来源页面 | 保存规范的 `https://gamebanana.com/mods/<modId>` 到 provenance.sourceUrl | 现有来源与版本面板 |
| Mod 版本 | 站点 `_sVersion`；缺失时留空，不以下载日期/文件名伪造版本 | 来源与版本面板 |
| 导入时间 | 成功提交本项时由主进程记录 | 来源与版本面板 |
| 作者、简介 | 站点作者/提交者与简介；保留可用的作者贡献原文，不从 HTML 执行内容 | 现有 metadata + 只读来源快照 |
| 站点标题 | 保留站点标题；不自动把不合法或很长的标题用作目录名 | 只读“网站信息”区及下载任务 |
| 站点 Mod/文件 ID | 保存 provider、modId、fileId；同一个包的多个导入项绑定到同一文件 | 网站信息区 |
| 原分类 | 保存站点分类原文；仅对已明确的分类映射为本地标签 | 网站信息区/现有分类 |
| 角色 | 仅采用现有别名表能确定的角色名；不认识时保留原分类，不猜角色 | 现有角色标签 |
| 原文件信息 | 原文件名、下载地址、大小、可用摘要和摘要算法 | 网站信息区及任务记录 |
| 适用游戏版本 | 站点未明确提供则留空；不把 Mod 版本填入 gameVersion | 来源与版本面板 |
| 验证状态 | 新下载仍为 unverified；下载校验不能替代人工游戏验证 | 来源与版本面板 |
| 预览图 | 继续识别包内已有本地封面；首版不把在线封面抓取作为安装必需步骤 | 现有 Mod 预览 |

现有 `library-<game>.json` 保持 version:1，以可选 `remote` 字段增加原始站点绑定。旧记录没有 remote 时照常读取。provenance/metadata 仍允许用户编辑，但不得因此伪造或改变站点 Mod/文件 ID。

建议 `remote` 包含 provider、modId、fileId、title、author、description、category、fileName、downloadUrl、size、checksum、checksumAlgorithm。实际实现应有统一的读入验证和旧数据兼容规则。

### 5.2 与现有业务联动

- 改名、分类移动、启停、预设和重启保持稳定 ID 与站点绑定。
- 同一下载包拆分出多个 Mod 时，每项保存同一站点文件来源，独立管理启停、分类和删除。
- 手动修改作者、简介、版本等字段时保留用户编辑和原始站点快照，不通过后台请求自动覆盖。
- 使用本地文件替换内容后，沿用现有版本历史及验证重置行为；清除当前内容的文件级 remote 绑定，保留可用来源链接。旧绑定随替换前恢复副本保存，避免新内容仍被宣称为原站点文件。
- 删除、恢复及完整快照应包含绑定；恢复旧内容时恢复对应旧绑定。
- 安装新项不自动加入预设或互斥组。启用时使用现有共享规则，不根据网站角色分类自动让所有配件互斥。
- 浏览和下载期间，不清空其它页面未保存的设置或 Mod 信息草稿；双窗刷新通知继续使用现有事件。

## 6. 桌面接口与任务状态

这些是拟采用的契约；目前代码中的同名草稿接口尚未完成验证，不视为已交付 API。

| 方法/通道 | 输入 | 输出与约束 |
| --- | --- | --- |
| setModBrowser / market:view | gameId、可见区域 bounds 或 null | 显示/隐藏内置视图；只能选择配置好的网站，不接受任意 URL；校验并限制区域到窗口内容范围 |
| modBrowserStatus / market:status | 无 | 网页地址、载入/错误、前进后退能力、下载任务摘要；响应不等待安装文件队列 |
| navigateModBrowser / market:navigate | back / forward / reload / home | 仅固定导航动作；返回最新浏览器状态 |
| modDownloadAction / market:download-action | taskId + cancel / retry-download / retry-binding / retry-install / install-current / show-file | 主进程按任务当前状态校验；安装动作入队，取消/查看保持响应；不接收 renderer 指定的磁盘路径或下载 URL |
| saveGamePaths（复用） | gameId + paths 局部修改 | 继续保存可调整 Mod 目录；新任务读取最新已保存值 |
| onDesktopChange（复用） | 订阅 | 安装完成或部分提交后，通知主窗/浮窗重读实际库；离开页面解除订阅 |

`install-current` 表示用户明确选择使用当前目录；执行前主进程展示原/新目录并确认，再按最新配置校验。`retry-install` 复用完整缓存，重验文件与目标，不能跳过游戏、来源、冲突和路径检查。

任务摘要建议包括：taskId、gameId、targetRoot、站点 Mod/文件身份、fileName、title、stage、receivedBytes、totalBytes、archiveReady、message、逐项结果、importedIds、创建/更新时间。缓存磁盘位置由主进程维护，不提供任意本地读写接口。

状态流：

```text
读取信息 → 下载中 → 校验中 → 解包/安装中 → 完成 / 部分完成
                    └→ 等待选择目录 → 用户明确选择后重验并安装
任一阶段失败 → 失败（按可用缓存和失败原因提供相应重试）
安装提交前取消 → 已取消
退出时尚未完成 → 下次启动标为已中断，不自动续装
```

安装提交期间禁用该任务取消，避免把已写入的部分结果当作“完全取消”。下载任务与管理器更新安装互斥：存在活动下载/安装时，更新器提示先完成或取消 Mod 任务；进入管理器更新安装状态后拒绝启动新 Mod 任务。显式退出可结束下载，已提交的导入结果保持；不取消已经开始的文件提交一半。

## 7. 页面设计

- 左侧栏：新增“寻找Mod”，使用现有搜索图标、选中样式、折叠栏提示和键盘焦点样式。
- 页面顶部：标题、后退/前进/刷新/游戏首页、只读当前 URL、载入或失败提示。地址不是任意网址输入框。
- 页面主体：网站视图占据主要空间；下载区位于右侧，可滚动，保持站点浏览时仍能查看进度。
- 下载区顶部：显示绝区零当前保存的安装目录及“更改目录”入口；未配置时明确说明先完成设置。
- 每个任务：站点标题、原文件名、游戏与目标目录、当前阶段、进度、成功/失败详情和与状态相符的操作按钮。
- 完成任务：显示“已安装 N 项，默认停用”，提供“查看已安装 Mod”；多项包列出具体项，不只显示总数。
- 异常任务：目录变化、同名冲突、下载失败、无法绑定和校验失败使用可区分的文字。重试不偷偷变成替换已有 Mod。
- Mod 详情：在现有来源与版本面板内增加只读“GameBanana 网站信息”；可查看标题/作者/原分类及来源身份，现有可编辑表单保持。
- 旧入口：更多菜单中的“打开 Mod 网页”改为进入“寻找Mod”；设置页移除可编辑的 Mod 网页地址，改为固定网站说明。旧 marketUrl 字段保留兼容读取，但不决定新网站入口；更新发布页设置不受影响。
- 终末地：显示未配置提示，可看既有绝区零下载任务，但不能把任务安装目标切换成终末地。

## 8. 实施顺序与交付门槛

| 阶段 | 具体工作 | 完成门槛 |
| --- | --- | --- |
| A：核对并收敛草稿 | 对照方案整理已有代码；修复类型错误；核实站点详情、下载跳转、文件域名和登录下载场景 | 明确支持域名/路由/字段，核心类型可检查；未支持场景明确提示 |
| B：浏览器与页面 | 原生视图生命周期、导航隔离、侧栏/页面接入、设置固定网站说明、区域同步 | 实际主窗可浏览指定网页；离开页面/缩放/侧栏变化后不遮挡 UI；网页无本地桥接权限 |
| C：下载任务 | 接管真实浏览器下载、进度/取消、缓存、并发限制、任务摘要持久化 | 可受控下载与取消；不弹任意保存路径对话框；重启后状态诚实；来源无法绑定不自动安装 |
| D：安装与信息绑定 | 校验/识别、多项导入提交、同名与重复处理、默认停用、目录变化选择、双窗刷新 | 文件、稳定 ID、来源与作者版本一致；失败不覆盖现有 Mod；新目录行为通过实际文件测试 |
| E：回归与说明 | 正常/异常测试、源码窗口验证、桌面接口文档与 API 清单同步、进度更新 | 静态门槛与自动测试通过，实际源码窗口流程有证据；已验证与未验证范围分别记录 |

先完成核心链路，不同时加入自建搜索索引、账号后台、社区功能、自动 Mod 版本升级、网盘登录适配、云同步或 Mod 故障排查向导。已有下下版本体验优化排期继续保留。

## 9. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 进入绝区零“寻找Mod” | 内置显示指定首页；站内搜索、详情和下载页正常；导航按钮反映实际状态 |
| 网站不可达/请求失败 | 显示错误与刷新方式；其它管理功能可用；不伪造下载成功 |
| 切页、侧栏折叠、缩放、DPI | 网页区域与占位区域一致；不盖住侧栏、标题、任务和弹窗；离开后视图消失 |
| 普通 ZIP、7z、RAR | 浏览器事件进入内置任务，校验后导入为停用状态，并绑定正确的信息 |
| 一个包包含多个 Mod | 每项有独立 ID，共享正确文件来源，成功项与失败项同时显示 |
| 同名目标已存在 | 原目录内容、ID、草稿与恢复记录保持；冲突项报告失败，不静默覆盖 |
| 同一站点文件再次下载 | 按当前库有效绑定提示已安装，避免重复自动导入；用户替换仍走已有显式流程 |
| 站点游戏不是绝区零/文件 ID 不匹配 | 不安装；不能仅靠文件名推断归属；显示原因 |
| 站点元数据失败/缺少版本 | 读取失败可重试，不做错误绑定；仅缺少可选版本时版本留空 |
| 大小/摘要不一致、危险包、无 INI | 不安装到正常库；明确报告校验/解包/识别原因 |
| 下载中取消 | 任务取消，未开始安装；没有新库记录；完整包是否可用按实际状态展示 |
| 用户调整设置目录 | 未保存不生效；新任务用新目录；旧任务进入等待选择，确认后才按当前目录安装 |
| 下载期间切换游戏/离开页面 | 任务仍属于绝区零和原目标；不误装到终末地；返回后能查看任务 |
| 安装完成后启用、加入预设 | 保持当前稳定 ID 与信息；现有互斥组约束和预设行为正常 |
| 改名、分类、替换、删除恢复、快照 | 绑定按第 5 节规则保持或清除；恢复可取回旧绑定；旧格式库可读 |
| 远程页面尝试访问 IPC/本地文件 | 访问失败；管理器可信页面的合法功能仍正常 |
| 退出重启/更新安装 | 完整包和任务结果可重读；中断不冒充完成；不自动续装；更新与 Mod 文件提交协调 |

验证分层：

1. 纯规则与真实文件测试：URL/路由/元数据绑定、摘要、危险压缩包、逐项冲突、默认停用、可调目录、数据兼容与恢复。
2. 原生下载与源码窗口测试：在隔离用户数据目录，用受控网站响应/下载样本驱动实际 WebContentsView、DownloadItem、生产 IPC 与文件导入；不能只用直接调用导入器代替浏览器事件测试。
3. 真实网站联调：验证首页、详情、跳转链和一份可正常获取的 Mod 下载；遇到网站访问/登录限制时记录限制，不将受控样本测试说成真实网站成功。
4. 人工体验：确认操作位置、错误提示、目录调整和界面遮挡情况；游戏内加载及新便携包验收另行安排。

拟执行门槛：`npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run api:inventory`、`npm.cmd run api:check`、`npm.cmd run build`，以及本轮新增的来源/下载测试和源码窗口验证。接口数与测试数以最终实测为准，不沿用上轮结果作为本轮已通过证明。

本轮计划不执行管理器 Release 下载验证、安装器/便携包专项验收或真实游戏启动，保持用户此前的范围安排。
