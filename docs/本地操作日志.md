# 本地操作日志

## 当前统一日志系统（0.0.6，2026-10-16）

设置 → 诊断 → 日志：提供“打开日志目录”和“分析日志／刷新日志分析”。默认实际目录为管理器安装目录下的 `log`；源码模式使用项目根目录。目录不可写时回退到 `userData/log`，页面展示实际路径与回退状态；两处均不可写时保留有界内存记录、明确报告写入失败，业务结果不因日志故障改变。`KMM_DATA_DIR` 隔离配置和日志 profile，不改变默认安装目录日志位置。

底层 `ApplicationLog` 负责 JSONL、脱敏、串行写入、轮转、会话标记和本地分析；`OperationLog` 作为调用切面统一记录所有业务 IPC，复用原有副本／文件事务引用。`AsyncLocalStorage` 将请求、嵌套操作、异步任务和事务检查点关联起来。界面通过 typed preload 上报受限控制元数据；远程 GameBanana 页面没有日志或其它桌面 API。

| 范围 | 当前记录 |
| --- | --- |
| 主窗／浮窗 IPC | 请求、队列等待、执行起止、成功／失败／取消／部分结果、操作 ID、父操作 ID、来源、游戏、对象 UUID 和固定枚举；包括读取、状态轮询、设置、更新、部署和权限拒绝 |
| GUI | 按钮／字段变更事件和页面切换的控制标识；不记录输入值、动态 Mod 名称或键盘输入 |
| 后台任务 | 只读任务开始／结束／取消／失败，任务 ID、耗时；冲突检查记录候选 hash、Mod ID、数量和完整性，下载记录阶段／字节数／任务 ID，文件提交记录事务 ID 和持久检查点 |
| JS 与进程 | renderer error、unhandledrejection、React 根错误、主进程致命异常、进程 warning、renderer／子进程退出原因与退出码、加载及 preload 失败、无响应／恢复响应 |
| 生命周期 | 产品及 Electron／Node 版本、启动、主窗加载、正常退出；下一次启动识别缺少正常退出标记或已有致命记录的会话 |
| 本地原生崩溃转储 | Crashpad 目录为 `log/crashes/<profile>/`，明确关闭上传；启动时只清理已识别 UUID 文件名的旧 `.dmp`，最多保留 10 项／128 MiB，之后新生成的转储在下次启动时整理 |

主日志名为 `application-<profile>.jsonl`，profile 为数据目录的不可逆摘要前缀，独立配置实例不会竞争同一个写入文件。单文件 4 MiB，另保留 `.1`–`.5`，每 profile 约 24 MiB。单条超过 32 KiB 时保留身份、结果及截断标记。致命错误另同步写 `fatal-<profile>-<session>.jsonl`，每会话只保留首个致命错误，启动时保留最近 10 个此类文件；`session-<profile>.json` 保存生命周期状态。这些限制不等同于所有 profile／转储的全局总额。

JSONL 核心字段包括 `schemaVersion:2`、UTC `time`、`level`、`component`、`event`、`sessionId`、`pid`、`operationId`、`parentOperationId`、`action`、`origin`、`gameId`、`id/phase/result`，以及受限错误的 `name/code/message/stack`。副本和事务引用沿用原记录 ID。业务参数只保留白名单元数据，不序列化原始配置、INI、Cookie、请求体或凭据；异常文本过滤网址、带标签凭据和绝对路径。原生 `.dmp` 可能含内存信息，不纳入脱敏诊断报告或自动上传。

本地分析只读取当前 profile 最多 8 MiB／20,000 条的保留日志，并明确给出截断、坏行与写入失败数量。选定游戏只显示其事件和共享进程事件。分析包含静态冲突候选、致命错误、renderer／子进程异常退出、磁盘不足、权限、占用、下载／校验错误，以及异常会话中未观察到结束的操作；返回时间、会话、操作／父操作和关联任务 ID 供核对原始日志。

候选 hash 重叠是历史静态检查线索，不证明游戏内渲染冲突；缺少正常退出标记可能来自强制结束、断电或故障，不能单独判定原因；有开始无结束的操作可能已部分提交，恢复以持久事务记录为准。日志不是不可篡改审计、断电恢复协议或任意系统故障的自动根因证明。更早会话或已轮转删除的记录不能恢复。环境诊断及其脱敏导出会纳入当前统一日志分析，同时继续读取旧 `userData/logs/operations.jsonl`；旧文件不自动搬动或删除。

日志 API 为 `logReport(game)`、`openLogDirectory()`、`reportRendererEvent(event)`，当前完整桌面 API 为 102 异步方法 + 1 事件。前两项仅主窗使用；上报仅可信主／浮窗可调用，验证字段、大小及游戏，超过每秒 200 条时记录限流警告，不为遥测递归创建操作 span。打开目录仅使用主进程确定的位置，不接受 renderer 路径。

源码门禁：255/255 完整测试、类型检查、102+1 API 清单和构建通过。`npm.cmd run smoke:logging` 的源码窗口验证了诊断入口、真实双 Mod 静态重叠、主／浮窗调用、受控界面错误／拒绝、敏感参数排除、实际 renderer 崩溃，以及核实 PID／EXE／隔离 profile 后强制结束 Electron 主进程、重启识别。目录打开由驱动记录目标，未将 Explorer 人工体验作为已验收；未启动真实游戏／XXMI，未做 Release 或整包更新验收。

0.0.6 本轮最终窗口证据：[报告](../.run-data/logging-smoke/run-8913zC/report.json)、[诊断截图](../.run-data/logging-smoke/run-8913zC/diagnostics.png)；完整测试为 `.run-data/v006-full-tests-retry.log`，首轮阻塞及独立复核见[版本验收](0.0.6版本说明与验收.md)。前轮 `run-etD2yv` 和 `.run-data/unified-logging-full-tests.log` 保留为历史证据。核心专项还以独立真实 Node 子进程验证致命堆栈和未结束操作，以及 file URL 堆栈脱敏后仍保留相对文件位置和行列号。更新辅助函数在隔离目录验证 `Mods` 与 `log` 的转移／回退。日志目录已加入 Git 忽略和更新保留目录；新更新包禁止携带这些用户目录。

## 位置与保留范围

日志位于管理器数据目录的 `logs/operations.jsonl`，可以用文本编辑器查看。默认数据目录由 Electron userData 决定；设置 `KMM_DATA_DIR` 时日志写到对应隔离目录。窗口验收的实际文件示例：[主窗和浮窗日志](../.run-data/priority-smoke/run-dO3hqo/data/logs/operations.jsonl)。

当前文件最多 2 MiB，另保留 `operations.jsonl.1`、`.2`、`.3` 三份滚动日志，总体积上限约 8 MiB。`.1` 为最近一次滚动，`.3` 最旧；超过范围时只移除最旧日志，不清理备份或 Mod。每条记录最多 16 KiB，大批次的对象 ID 列表最多保留前 40 项，同时记录实际数量；单个备份/提交引用各自有独立记录。

## 记录内容

覆盖主窗和浮窗的导入、替换、移除、启停、改名、分类、信息/来源修改、互斥组、封面、预设、INI 保存、备份创建与恢复，以及内置浏览器下载页安装。扫描、搜索、读取状态、网页浏览和设置正文不写入操作日志。

| 字段 | 含义 |
| --- | --- |
| `version` / `time` / `id` | 日志格式版本、UTC ISO 时间、本次操作 ID |
| `action` / `origin` / `gameId` | 操作通道、main/floating/browser 来源及所属游戏 |
| `kind` / `enabled` / `targetIds` / `targetCount` | 经过筛选的操作类型、请求启停选择、对象 ID 与数量；不保存完整参数 |
| `phase` | start 开始、reference 关联副本或目录提交、finish 业务返回 |
| `durationMs` / `result` | 操作耗时、成功/部分失败/失败/取消/等待互斥选择，以及处理/导入/问题数量 |
| `savedId` / `importedIds` | 新建预设或互斥组 ID、已导入 Mod ID，位于 result 内 |
| `reference` / `referenceIds` | 已完成备份或目录提交记录的 ID，可与 removed 或 pending-operations 对照 |

结果状态分别为 `succeeded`、`partial`、`failed`、`canceled`、`awaiting-choice`。失败只保留固定分类，如磁盘不足、占用、权限、同名冲突、缺失或中断；不写入原始错误全文。日志不包含 Cookie、账号凭据、来源/下载 URL、绝对路径、配置正文、INI 正文、作者/说明或来源版本表单值。

开始与结束使用同一操作 ID，备份和提交引用也关联该 ID。强制退出后有 start 而没有 finish 时，只能说明未观察到正常结束；结合“备份与恢复”的中断项目核对，不能据此推断整批都未提交。日志记录业务服务结果，不表示游戏加载、兼容性或界面通知已成功。

## 可靠性与验收

写入串行化，正常退出等待文件操作及日志队列。日志空间或权限故障只产生一次通用警告，不改变业务返回，也不回退已提交内容。写入中断可能留下残缺行；之后的完整记录会另起一行，解析时跳过残缺行。本日志不是断电审计协议，也不替代中断恢复记录。

类型检查、102 项完整测试、55 + 1 API 检查与构建通过。专项测试验证真实替换/预设与副本关联、结果分类、敏感值排除、并发隔离、滚动上限、日志 ENOSPC 不影响业务，以及半行写入后的后续记录。既有强制退出专项还验证两游戏中断时留下 start 和提交引用而没有伪造 finish。

实际源码窗口验证主窗、浮窗、互斥选择、预设、替换副本及重启后的日志；受控网站窗口验证下载页安装以 browser 来源记录，三次完成记录的新增导入数量为 2、2、0，已有安装没有被算成新导入。原生选择器与确认由测试驱动代答，没有新增真实游戏、真实 GameBanana、打包或 Release 验收。
