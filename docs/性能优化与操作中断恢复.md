## 性能改动与实测

扫描使用路径索引，逐项读取最多并行 12 项，复用目录条目判断 INI；未发生数据变化时不重写库文件。扫描仍重新遍历文件系统，外部新增、删除或修改不会因扫描缓存被隐藏。角色封面目录复用刚扫描出的角色集合，图片按当前文件身份、大小和时间校验后复用缓冲；每个图片缓存最多 32 MiB / 128 项。

搜索索引在库变化时建立。超过 160 项的 Mod 列表、预设成员和互斥组成员按可见区域渲染；复选状态和详情草稿保存在列表之外。互斥组折叠时不创建隐藏的成员控件。角色计数一次汇总，预设成员按 ID 索引。预设应用在开始和结束扫描，中间更新已改变的成员；同名冲突、父目录限制和互斥选择继续校验，已经符合要求的目录无需重复提交。

基线与复测均使用本机 Windows / Node 24、同一独立库：1000 个 Mod、2 个角色，每项 2 个 INI 和 4 个小纹理文件。扫描及封面各 3 次取中位数，预设应用每组 1 次，窗口搜索使用相同 5 个查询取中位数。预设测试只改变 16 项；千项成员的窗口测试验证编辑及保存，不代表千项同时启停的耗时。

| 测量 | 改动前 | 最终复测 | 测量终点 |
| --- | ---: | ---: | --- |
| 全库扫描 | 1586.40 ms | 389.62 ms | 服务返回完整库 |
| 扫描后的角色封面读取 | 1590.52 ms | 35.03 ms | 封面集合读取完成 |
| 预设切换 16 项 | 30855.41 ms | 1639.59 ms | 文件提交及最终扫描完成 |
| 同一预设再次应用 | 13797.90 ms | 732.35 ms | 无目录变化，仍读取最新状态 |
| 启动到概览首张图片就绪 | 5567.41 ms | 2041.63 ms | Electron 源码窗口图片 complete |

窗口数据含 Playwright 操作和响应时间，不是 GPU 绘制延迟。测量属于这台机器与该受控库，不能推导真实大纹理包、所有库规模或真实游戏的性能。基线在改动前捕获，当前脚本只测量当前代码，不会通过更换 label 恢复旧实现。

## 文件提交与恢复

文件夹/归档导入、网站安装、替换、移除、启停、改名、分类和内容恢复共用受控目录提交。完整内容先准备，再保存操作记录，随后移动旧目录、提交新目录、原子替换相关元数据，最后清理旧暂存。临时目录与目标位于同一磁盘，以 `DISABLED_.kmm-operation-` 开头，管理器扫描排除这些目录；loader 仍需要已有的 DISABLED 排除规则。

单个 Mod 提交将目录与库记录一起管理。完整快照还保存该游戏封面、库、预设及游戏路径的恢复信息；恢复游戏路径时保留另一游戏路径、当前选择和其它设置。INI、设置、预设及封面文件先写临时文件再替换，INI 保存会在提交前再次检查原摘要。Windows 短暂占用采用有限重试，不先删除旧文件来绕过锁定。恢复副本在复制完成后才写可恢复记录，复制未完成的副本不会伪装成完整备份。

磁盘不足或占用导致提交失败时，尝试恢复原状态；无法安全回退时保留原目录、暂存副本和操作记录，并明确提示处理。启动后仍有未完成操作的游戏与根目录暂停管理，另一游戏不受该有效记录影响，不自动继续安装。

使用方法：

1. 按错误提示进入左侧“备份与恢复”。
2. 选择“中断操作”，查看游戏、根目录和影响范围，点击“处理所选中断操作”并确认。
3. 管理器核对目录身份与元数据后回退到操作前状态。已经提交的新内容保留为“已回退，新内容副本”，页面显示人工核对位置；已完成但清理受阻的记录只清理暂存。
4. 如果外部已替换目录、修改元数据或临时归属不可信，停止自动处理并保留内容，需人工核对。解决磁盘空间、文件占用或目录设置问题后，再重试原操作。

记录位于 `userData/pending-operations/<id>.json`，前后元数据位于同名子目录，目录内容副本位于记录指向的同盘受控暂存区。只清理经过路径和归属校验的自身临时目录，不自动清理回退后保留的新内容。

批量和预设采用逐项提交，已完成项保持完成，未完成项可回退；没有把整批扩展成全部成功或全部撤销的全局事务。单文件原子替换解决进程退出和写入失败时的截断问题，但本轮没有实现断电时的磁盘同步协议，不承诺硬件损坏或断电恢复。
