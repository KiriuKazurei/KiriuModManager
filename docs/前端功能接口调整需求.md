# 前端功能接口调整需求

更新日期：2026-10-12。本文记录 P2–P4 的业务状态与调用连接需求；样式、布局、视觉及页面实现由 Cursor / GUI Agent 负责。功能实现代理不再修改 `src/renderer`，也不回滚其中已有工作。

当前全面接口与调用规则见[桌面接口文档](桌面接口文档.md)。本文仍是 P2–P4 的有效 Cursor 功能待办与验收要求，不是被废止的旧接口说明。

## 1. Mod 详情未保存草稿与跨窗口刷新

### 已确认的正常操作问题

原 `ModPage` 对 `selected` 对象的每次更新都会重置名称、作者、说明及分类草稿。实际复现：主窗口选择同一个 Mod，填写未保存的名称、作者、说明；使用快速管理浮窗停用该 Mod；主窗收到 `desktop:changed` 并扫描后，输入恢复为旧名称和空作者/说明。目录实际已停用，但用户没有保存详情编辑。

证据：`.run-data/modules-review/phase2-draft-probe/run-PlZ93H/report.json` 与 `main.png`；`physicalToggleViaFloatingUi=true`。这是业务状态问题，不是布局问题。

### 当前代码状态与 Cursor 归属

严格前端边界生效前，已存在 `src/renderer/mod-draft.ts`、`ModPage.tsx` 的草稿接入，以及 `tests/mod-draft.test.ts`。这些代码及 GUI Agent 后续变更作为当前工作保留；功能代理不再修改页面或执行旧的 `phase2-edit-renderer.cjs` 辅助脚本。

已有 helper 的意图是按 `gameId + modId` 和逐字段保存基线合并：同身份外部刷新保留明确编辑的字段，未编辑字段采用实际保存值；自己保存只清除本次提交的字段；切 Mod、游戏或目录上下文清除旧身份。纯 helper 测试已通过；对当前 GUI 只读复验 `.run-data/modules-review/phase2-draft-probe/run-ukDksA/report.json` 已确认真实浮窗启停后，主窗未保存的名称、作者、说明保持。其它逐字段提交与换身份边界仍由 Cursor 按下面清单确认，不能把此项通过扩展为所有草稿行为均已验收。

Cursor 需要确认的行为：

- 同 ID 浮窗启停、重新扫描、图片选择和取消，不清除名称、作者、说明、分类、角色或外观的未保存编辑。
- 外部更新未编辑字段时显示最新实际值；本地明确编辑的字段保留。不能只按对象引用判断换了 Mod。
- 名称改名成功后接受实际名称及大小写，保留其它未保存信息；改名失败保留输入，不能显示成功。
- 保存信息成功后接受实际规范化 metadata，保留未提交的名称草稿；保存信息不能移动实际目录。
- 分类移动仅提交 `category/character/appearance`，成功后接受实际标签，保留未提交的作者/说明。允许空外观；不能因后台刷新额外保存作者或说明。
- 切换 Mod、游戏、已保存根或确认移除后，不把旧 Mod 草稿带给新身份。一个操作返回时如果用户已切换选择，不应强制重新选择旧 Mod。

### 可执行验收

先构建当前源码，再以 `.run-data` 隔离数据运行 `.run-data/modules-review/phase2-draft-probe.mjs`。探针使用真实主窗字段与真实浮窗启停，并断言未保存名称、作者、说明保持。其它提交/换身份路径由 `tests/mod-draft.test.ts` 和 `smoke:mods -- --functional` 的实际目录、身份及返回结果校验补充；纯 helper 测试不能替代窗口接入验收。

## 2. P2 桌面契约与调用约定

所有调用仍经 `window.kmm`，类型见 `src/shared/contracts.ts`，生产 preload 见 `src/preload/index.ts`，handler 见 `src/main/index.ts`。本节 P2 方法签名不变；P4 两项兼容新增方法见第 8 节。返回统一为 `Promise<Result<T>>`，错误为 `{ok:false,error:string}`；页面应保留相关输入、展示错误，不把返回错误或取消当作成功。

| 方法 | 参数 | `Result.value` 与业务含义 |
| --- | --- | --- |
| `scanMods` | `game: GameId` | `LibrarySnapshot`；以已保存 Mod 根为准，含稳定 ID、实际启停、标签及警告 |
| `addGroup` | `game, kind: category/character/appearance, name` | 新快照；只保存分组，不创建空目录 |
| `operateMod` | `game, id, operation` | 新快照；`toggle(enabled)`、`rename(name)`、`metadata(metadata)` 或 `classify(category,character,appearance)` |
| `importMods` | `game, kind: folder/archive` | `ImportResult`；用 `importedIds` 和 `errors` 分别呈现成功与失败，允许部分成功；取消为 `canceled:true`，不可宣称已导入 |
| `replaceMod` | `game, id, kind` | 新快照或 `null`；取消不修改文件。替换保留身份、信息、停用状态和用户预览，旧内容有副本 |
| `deleteMod` | `game, id` | 新快照或 `null`；原生确认取消为 `null`，成功将文件移出读取目录并保留恢复副本 |
| `cover` | `game, id` | Mod 预览 data URL 或 `null`；与角色封面独立，支持 PNG/JPEG/WebP/GIF |
| `chooseCover` | `game, id` | 新快照或 `null`；原生选择器负责路径，renderer 不传绝对来源路径 |
| `characterCovers` | `game` | 角色名到图片 data URL 的映射；无默认或自定义图的角色可缺键 |
| `chooseCharacterCover` | `game, name` | 新快照或 `null`；仅可解码 PNG/JPEG、最大 10 MB；拒绝 WebP/GIF 时保留原图片与引用 |
| `onDesktopChange` | callback | 解除订阅函数；Mod 操作通知用于重读实际快照，不是清空同身份编辑草稿的授权 |

原生选择器和删除确认都在主进程。正式 bridge 不接收任意待导入或待删除文件绝对路径，也没有任意 EXE 执行入口。文件管理成功不代表真实游戏已经加载、停用或刷新。

## 3. 路径推断与界面数据

后端已对新发现或新导入的记录采用当前库注册分类（默认分类与 `addGroup(category)`）：单层已知分类只填 category，保持 character 为空；已知分类/角色两层路径允许 appearance 为空；未知短路径保留原角色/外观解释；三层及更深路径保留原分类/角色/外观规则。`DISABLED` 前缀按 loader 现有规则处理。已经保存的 metadata 不重新推断，避免覆盖用户信息；旧错误标签也不会静默迁移，用户可按实际目录保存信息。

Cursor 的未分类入口应以 `metadata.character` 是否为空判断，而不是目录是否在根级。分类移动与保存标签必须分开调用；空外观不能阻止移动。大小写改名成功应采用返回快照的真实名称，不仅更新显示文案。

## 4. 图片与取消反馈

默认 WebP 角色立绘由 Chromium 图片元素解码；自定义角色图走主进程 PNG/JPEG 校验和 nativeImage 解码，两者不能混为同一格式限制。当前默认佩丽卡资源实际是 PNG，原 gallery 基线通过，并不存在已确认的该资源格式失败。新功能测试改用独立有效 PNG/JPEG 替换图，同时覆盖真实 WebP/GIF 拒绝与原图不变；Mod 预览继续单独验证 WebP/GIF。

选择器取消不显示“已保存”或“已替换”。解码、格式或大小失败应显示 `Result.error` 并保留原图；跨游戏和重启后的图片引用从主进程重读，不在前端复制另一游戏状态。

## 6. 本轮验收边界

功能窗口脚本支持 `--functional`：保留导航、选择器、错误/取消、稳定 ID、图片解码和实际文件断言，明确不验 CSS、窗口宽度或排版。默认模式原有布局断言保留，纯布局失败交 GUI Agent；功能代理不修改页面来迎合断言。

P2 收口时未推进预设、INI、候选冲突或恢复模块重构；gallery 已有完整快照流程只作为角色图片兼容回归。当前用户明确本轮不生成便携包/ZIP，也不执行 packaged 验证（deferred-by-user）；旧 release 和框架验收包保留。

## 7. P3 通知与 INI 接入注意

P3 已授权并实施后端收口，renderer 仍不修改。预设保存/删除、INI 保存、手动完整备份成功后新增现有 `desktop:changed` 刷新通知，payload 不变，`settingsChanged:false`。gameId 表示当前选中上下文，不是操作参数游戏的回执；具体方法与返回见 `docs/接口调整说明.md`。

INI 保存现在按保持编码/BOM/换行后的最终字节拒绝超过 4 MiB 的输出，返回 error 时原文件与副本数保持。Cursor 应展示实际 Result.error，保留未保存输入；不要提示保存成功或因失败清空编辑。保留 digest 陈旧内容保护，外部文件改变后用户明确重新读取再编辑；自动刷新不能覆盖未保存文本或预设名称/成员。

当前只读 GUI + 生产浮窗 bridge 复验 `.run-data/modules-review/phase3-bridge/run-cPRBXO/report.json` 已确认未保存预设名称与 INI 原始文本保持，并确认另一窗保存产生真实事件。不能把未测试的成员/快捷键编辑草稿路径称为全部通过；这些路径仍按同身份逐字段基线保留。P2 第 5 节两项反馈已经修复。

## 8. P4 局部保存已接入页面

`saveGamePaths(game,patch)` 与 `saveDesktopPreferences(patch)` 返回 `Promise<Result<Settings>>`。`SettingsPage` 和 `DesktopSettings` 已分别调用这两项，只提交 dirty 字段。`settings-draft.ts` 的 `acceptSubmittedGamePaths` 与 `acceptSubmittedPreferences` 在成功后只接受本次提交且未被再次编辑的字段。空 patch 在本地反馈「无待保存更改」。错误保留输入。`App` 继续 `selectGame`，并在 `settingsChanged` 时接收完整 Settings。旧 `saveSettings` 保留完整替换，当前无页面消费者，清单为 compatibility-only。保存游戏路径不切游戏。检测、同步、部署仍走原接口。

字段白名单、调用示例和验收矩阵见 `docs/接口调整说明.md` P4 节。清单已由 `npm.cmd run api:inventory` 与 `api:check` 核为 connected。迁移前双窗 IPC 证据 `phase4-patches/run-U6VyMQ/report.json` 的 frontendMigrated 为 false，只代表当时产物。当前页面验收见 `.run-data/cursor-acceptance/acceptance-report.json`。
