# 后续版本迭代规划

更新日期：2026-10-13。本文记录用户确认的版本取舍。更新器已接入 0.0.1，三项重点功能也已完成源码/接口/页面接入；下下版本体验优化仍为规划。后续正式版本号和日期暂未确定。

现有未完成工作继续以[完成进度与未完成事项](完成进度与未完成事项.md)为准，包括未覆盖的预设成员/快捷键草稿与人工验收、真实外部集成，以及用户延后的新便携包验收。局部保存和两项页面反馈已经完成，不在这里重复列为待办。本规划不替代这些事项，也不改变既有延后安排。

## 0.0.1：最高优先级发布前置工作

用户已追加确认：立即实现管理器更新器，完成“检查更新 → 展示版本与更新说明 → 用户确认下载 → 校验更新包 → 退出后替换并重启”的版本，才作为准备打包发布的正式 0.0.1。默认更新来源为 KiriuKazurei/KiriuModManager。详细实现及验收边界见[管理器更新与发布说明](管理器更新与发布说明.md)。

更新器优先于下面三项；原有未完成事项和真实游戏/人工验收继续独立记录。用户随后明确“不用验证 release 下载，不用考虑便携包和安装的问题，确保更新器功能存在即可”，本轮以更新器源码、接口和页面接入收尾，停止安装/便携包专项验收，不自动发布测试包。

## 0.0.1 之后的下一个版本：重点迭代

三项均为用户标注的优先方向，不在本阶段加入其它建议功能。

当前实施及验收状态见[重点迭代功能说明](重点迭代功能说明.md)：批量管理、手动互斥组、来源与版本记录均已接入，尚未进行真实游戏或新便携包验收。此状态不等于正式发布。

| 功能 | 首版建议范围 | 验收重点 |
| --- | --- | --- |
| 多选与批量管理 | 多选 Mod，批量启停、修改分类、加入预设；明确筛选后全选的范围；逐项展示结果 | 成功与失败同时保留；实际文件与列表一致；稳定身份、未提交草稿和两游戏隔离保持 |
| 角色外观互斥组 | 用户手动建立互斥组、维护成员；启用一个成员时停用同组其它成员；不按角色名称自动把所有 Mod 互斥 | 单个、批量、预设和浮窗启用均遵守同一规则；批量或预设同时请求启用同组多个成员时，明确提示并要求选择，不能依赖执行顺序静默决定；部分失败后展示实际状态 |
| Mod 来源与版本记录 | 来源链接、Mod 版本、导入时间、适用游戏版本，以及人工验证状态；替换保留版本历史 | 来源和版本按稳定 ID 持久化；重启、替换、备份和恢复保持关联；旧数据可读取；人工标记不宣称自动验证兼容性 |

实施前按“底层框架 → 功能模块 → 对应接口 → 显示界面”细化：

- 底层框架：复用现有稳定 ID、游戏/目录上下文、主进程队列和恢复副本；明确新数据兼容与持久化规则。
- 功能模块：统一启停规则，使互斥组约束覆盖单项操作、批量管理、预设应用与浮窗；来源/版本记录关联现有 Mod 身份。
- 对应接口：设计批量逐项结果、互斥组读写与启用冲突处理、来源/版本记录读写；具体签名待方案确认，现有桌面契约不因本文自动变化。
- 显示界面：Mod 列表多选与批量工具、互斥组管理入口、详情中的来源/版本信息和历史。

建议先确定共享启停规则及数据结构，再接入批量管理和互斥组；来源/版本记录可独立推进。以上是实现依赖建议，不改变三项同属优先的决定。

## 下下个版本：体验优化

除暂缓的故障排查向导外，其余上一轮建议均归入本阶段。前三项技术质量工作单独列出，避免与产品功能混淆。

| 类型 | 项目 | 建议范围 |
| --- | --- | --- |
| 技术质量 | 大库性能基线与针对性优化 | 使用隔离库测量扫描、搜索、封面加载和预设切换；根据瓶颈决定缓存、增量扫描或虚拟化，优化后以同一条件复测 |
| 技术质量 | 操作中断后的可恢复性 | 核对磁盘不足、文件占用、复制中途退出后的原文件、副本和元数据；记录可恢复状态；不预设扩展为全局中断事务 |
| 技术质量 | 本地操作记录 | 记录导入、替换、启停和预设应用的时间、对象、结果及关联副本；限制日志体积并避免记录敏感配置 |
| 产品功能 | 预设应用前预览 | 展示将启用、将停用、保持不变、缺失成员、父目录阻挡和互斥组问题；确认后以最新状态校验执行 |
| 产品功能 | 启动诊断与诊断报告导出 | 汇总路径、运行库、Importer 版本、读取/排除规则、启用数量和相关日志；本地报告导出前隐藏敏感信息；不将启动请求成功视为游戏加载成功 |
| 产品功能 | 导入预检与重复内容识别 | 预览识别出的 Mod、同名项、文件数量与预计大小；用内容指纹提示异名重复；由用户选择处理方式 |
| 产品功能 | 备份空间管理与恢复预览 | 显示副本占用、保护指定快照、手动清理所选副本；恢复前明确覆盖范围；清理须明确展示目标，不默认自动删除 |

本阶段内部顺序待上一版本完成后依据实际使用反馈确定。预设预览需兼容前一版本的互斥组；性能优化须有测量证据。

## 暂缓

Mod 故障排查向导暂时不做，不纳入上述两个版本。重新排期需用户后续决定。

市场、账号、社区后台、云同步、其它游戏和自动更新未因本规划加入任何版本。
