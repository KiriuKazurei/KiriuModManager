# 第三批重点迭代详细实现方案

更新日期：2026-10-14。第三批覆盖剩余 **F01、F02、F12**。当前开发与验收基线是本地提交 **7854131**：源码 **0.0.4**，**151 项测试、80 个异步调用和 1 个事件**。本轮整理实施方案，尚未开发第三批功能，不修改版本号；第三批交付版本在正式开发时确定。

已完成的第一、二批不重新列为待开发。真实游戏、人工体验、打包／Release 和 V04 性能差异归因保持独立登记，见[后续版本迭代规划](后续版本迭代规划.md)。

## 1. 交付目标与默认行为

| 编号 | 用户最终能做什么 | 入口 |
| --- | --- | --- |
| F01 导入预检与内容去重 | 本地文件夹／ZIP／7z／RAR 和已下载的新 Mod 统一先看条目、目标、体积、重复与冲突，选择后再导入 | Mod 库导入按钮、下载页安装／重试 |
| F02 普通预设应用前预览 | 看清实际启用、停用、自身目录变化、未变、缺失、阻挡及预设外联动，确认后按同一计划执行 | 预设页“预览应用” |
| F12 预设清单导入导出 | 导出可移植的来源／版本／组合清单，在另一库匹配本地 Mod；可明确选择携带独立 INI 配置 | 预设页“导入清单”“导出清单／配置” |

建议开发顺序：**固定可比基线 → 公共证据／指纹 → F01 → F02 → F12 → 交叉回归与文档**。三项仍属于同一第三批，顺序由技术依赖决定，不改变此前优先度。

本方案确定以下产品行为，实施时同时写入更新说明：

- 新导入统一默认停用，包含本地目录与压缩包。当前本地导入可能直接启用，这是本批明确的行为调整；在线安装继续保持停用。用户后续手动启用时走既有依赖／互斥校验。
- 重复内容默认跳过，可明确选择改名另存；同名目标保持。此入口不覆盖或升级已安装 Mod，已有定向更新／替换入口继续负责换包。
- 导入清单只创建方案、配置副本或待匹配草稿，不启动下载、不导入 Mod、不切换当前状态。应用仍经过 F02 或已有独立配置切换流程。
- 不自动创建互斥组，不覆盖已有 Mod 的来源、收藏、标签、兼容性或依赖声明，不把文件校验标为人工兼容性验证通过。
- 本批不增加自动 Mod 升级、账号服务、云同步、载入优先级、通用故障排查向导或其它游戏适配。

### 2.1 上下文、任务与授权

原生选择器、任务和计划都固定 **gameId、已保存根、数据目录、创建时间、来源身份和证据版本**。切换游戏／目录不把旧计划变成新目标；UI 接收旧响应时按任务 ID 与上下文核对。

继续只让可信主窗创建计划、导出和执行。远程网页没有本地接口；renderer 只传任务／条目 ID、受限相对目录和用户选择，不能传任意绝对路径、压缩包路径、EXE 或删除目标。手动文件来源由原生选择器在主进程转换为短期 SourceRef；下载来源由已有任务 ID 解析。

“只读业务”与“写准备缓存”明确区分：

- 普通预设预览和已选清单检查只读业务文件，沿用无迁移采集。
- 导入准备可能解包、复制来源快照和生成指纹，只能写当前任务拥有的暂存区；结果 DTO 标记 `effect:'owned-cache'`，不冒称完全不写磁盘。
- 建议独立 `PreparationJob` 生命周期，复用现有进度／取消和有限并发实现；与 InspectionJob 共享最多两个后台采集名额，同一游戏只跑一个导入准备。不要引入可操作任意路径的通用任务 API。
- 长准备过程在主写队列外执行；创建上下文、提交与元数据发布进入主队列。读取进度／取消／窗口导航保持响应，不用全局 busy 锁住长时间指纹计算。
- 预览缓存有归属记录，任务结果十分钟过期、可执行 token 两分钟过期；每窗最多保留二十份计划。改变选择、目录或互斥决定要重新生成确认摘要。

取消／退出后不自动安装、应用预设或恢复永久操作。下载完整包和本地原文件保持；仅可删除自身已确认无引用的准备缓存。归属不明或被未完成提交引用时保留现场，通过恢复／空间页说明。

### 2.2 内容证据与指纹

新增 `content-fingerprint.ts`，给 F01 去重和 F12 匹配使用，明确算法／规则版本，不能用文件夹名、压缩包 MD5、文件大小、时间或网站版本代替内容一致性。

**`mod-tree-v1` 严格指纹**：去掉最外层 Mod 目录名，保留全部实际复制的普通文件，以 `/` 表示相对路径；按固定字节序排序，把带长度边界的路径、文件长度与流式 SHA256 汇总为树摘要。使用原始字节，不改 INI 编码、换行或正文；内部 DISABLED 目录名保留。目录改名或顶层启停不改变指纹，文件改变会改变指纹。

在 Windows 目标语义下另外检查大小写／Unicode 规范化后的路径冲突，不把两个碰撞条目折叠成一个。链接、ADS／越界、重复归档路径和特殊文件在准备阶段拒绝。

严格指纹包含预览图、用户 INI 和其它被复制文件；因此只修改封面或热键时可以不再完全一致，页面应显示“内容不同／尚未比较”，不能把相似资源自动标成重复。网站身份、同名和相同声明版本单独列为关联线索。

为控制大库成本：先用文件清单、数量、相对路径和大小筛出可能匹配项，再在预算内读取完整字节。派生缓存按游戏／根／稳定 ID／规则版本和文件证据区分；大小／时间仅用于筛选和失效，不足以直接给出“内容完全相同”的结论。确认跳过重复前必须有本次可核验的来源与库内容摘要；预算不足／文件变化显示未完成比较，不显示“未发现重复”。

指纹不写入来源／兼容性字段。缓存损坏可以忽略并重建，不能修改原库记录；业务记录和保护索引的损坏处理仍沿用现有保留策略。

## 3. F01：统一导入预检与内容去重

### 3.1 准备与识别

流程：**原生选择或下载任务 → 固定来源 → 安全列表／空间初检 → 受控快照／解包 → 发现条目 → 指纹与重复检查 → 选择条目和目标 → 确认 → 提交**。

| 情况 | 处理决定 |
| --- | --- |
| 单 Mod 根内有 INI | 作为完整整体候选，保留内部资源／子配置，不任意裁剪 |
| 包含多个可独立识别 Mod | 每个候选有稳定 entryId，可选择子集；取消选择的内容不提交 |
| 外层包装目录 | 展示实际有效条目与来源层级，目标名称可编辑，不把包装层级误当角色 |
| 根 INI 与子 Mod 混合、共享资源等歧义 | 标明复合／不确定；默认整体或跳过，不能自动拆成丢资源的多个 Mod。明确独立来源可重新选择后预检 |
| 无 INI、加密／损坏、超限、链接 | 给出明确拒绝或需人工处理，不创建有效 Mod 记录 |
| 当前两游戏库、data 或受控恢复／缓存与手动来源重叠 | 拒绝循环／跨库复制；已有下载任务缓存使用专门受信任引用，不接受伪造路径 |

文件夹来源要复制到任务拥有的完整快照，避免用户在预览后改文件造成预览／提交内容不同。快照过程前后检查原文件证据，变化则停止或重新准备，不能悄悄选择其中一版。压缩包固定身份与摘要；解包后核对实际路径、数量、体积和无链接。

仅执行仓库受控解包器，不运行包内程序、脚本、INI 命令或任何 Mod 提供的可执行文件。

### 3.2 预检内容与选择

每项显示：标题／原条目路径、INI 数量、逻辑体积、游戏归属、角色／分类建议及依据、相对目标、默认停用、冲突、重复证据和网站绑定状态。文件列表按需分页，初始 IPC 只发摘要。

两游戏共用流程，角色建议来自各自字符／别名表。角色不确定时不猜唯一值，用户可选择已有分类目录或新建受限相对目录；不能放入另一个 Mod、隐藏资源目录或当前根之外。

默认选择可导入且无阻断的项；完全重复项默认跳过。同名冲突必须改目标名称／目录或跳过，提交前同时检查启用名与 `DISABLED_` 名，以及本次选项之间的碰撞。所有新项生成新本地 ID 与内容修订；保留来源版本、导入时间和已验证绑定，人工兼容性为未验证。

| 去重依据 | 页面结论与允许操作 |
| --- | --- |
| 本次完整树 SHA256 相同 | 完全重复；默认保持已有，可明确改名另存，不覆盖原项 |
| 同 GameBanana Mod/File/entryPath 且有效安装 | 显示已有绑定；只有当前内容核验一致才能同时显示“完全重复” |
| 同站点身份但本地改过内容／换过 INI | 已有关联、内容不同或未知；默认保持，需另存或转现有定向更新入口 |
| 同名、同版本、同压缩包但条目不同 | 仅关联／碰撞线索，不自动跳过合法不同变体 |
| 删除标记、目录缺失或旧根索引 | 不当成当前已安装副本，不复活旧身份 |

不自动合并内容相同但收藏／标签／预设关联不同的现有 Mod，不因为清单来源一致自动更新当前版本。

### 3.3 磁盘预算、提交与恢复

初始边界建议固定为常量：每次最多 32 个来源、100 个可提交候选；单归档继续不超过 50,000 项／2 GiB，准备过程总计不超过 200,000 节点／8 GiB；流式内容读取并发最多 2，库候选摘要读取另设 2 GiB 总预算。达到预算停止相应采集并明确未完成；数字可在有证据的评审后调整，不无声放宽解包保护。

分别计算数据卷的解包／快照、目标卷的准备副本和 FileOperations incoming 复制峰值、元数据及余量。现有流程可能复制两次，预检必须按实际实现计入，不能仅看压缩包大小或成品体积。每个真正提交项前重新检查空间；未知空间不能标为已证明充足，用户需看见估计边界。

确认 token 绑定来源／快照、选定 entryId、排除项、目标、当前根与库证据、重复决定、网站绑定和空间计算。根改变、包改变、目录出现同名项、库内容变化或 token 到期都要求重新预览。已有下载目录变更确认仍先执行，再生成新计划。

首版按候选逐项提交，沿用 `newOnly`、完整暂存及现有可恢复文件队列。单项成功后再发布其库记录／网站绑定；失败不留下看似有效的记录。缺空间或提交中断时停止剩余项；普通条目错误按明确策略报告可继续项，不能误报整批成功。

结果逐项区分 imported / existing / skipped / failed / interrupted，记录真实 importedIds。取消在完整条目边界停止；重启将准备／提交中任务标为需重新确认，不自动续装。主窗、浮窗和下载记录按真实完成项刷新。

下载安装和“安装重试”均走相同计划，支持只选择部分独立条目；已下载包保留。定向更新仍只选择一个替换条目。旧导入／安装接口通过同一解析器兼容；需要复杂选择或信息无法完整呈现时返回需重新预检，不恢复直接安装的旁路。

## 4. F02：普通预设应用前预览

### 4.1 唯一状态解析器

新增 `PresetPlanner`，预览与实际应用均调用同一 `resolve`，复用现有互斥与依赖规则，不在前端复制推导。普通预设读取已保存 members；未保存的名称／成员编辑先明确选择“保存后预览”或“使用已保存版本”，不自动保存、不默默应用旧草稿。

先解析互斥选择，再检查最终依赖投影，列出所有直接及预设外联动。多个冲突成员由用户选一个；缺失／停用提供者不自动加入启用组合。显式启用的成员与依赖／互斥选择相矛盾时阻断，不自动牺牲它来凑组合。

| 状态 | 必须显示的实际影响 |
| --- | --- |
| 将启用 | 当前自身停用、目标路径及前置要求；有停用祖先时不能只改内层名来启用 |
| 将停用 | 自身目录将增加停用前缀；包括预设外互斥成员与必须联动停用的依赖成员 |
| 父目录已停用、请求停用 | 区分实际已停用与仍将改变自身目录名，不能仅比较 enabled 得出“未变” |
| 保持不变 | 实际目录与所需状态均无变化；相同请求不会制造重复提交 |
| 缺失／已移除成员 | 显示原身份／可用名称；用户可明确排除后重算可应用子集，不能悄悄忽略 |
| 阻断 | 同名目标、源／目标链接、祖先停用、缺失依赖、低版本、互斥矛盾、未完成文件操作 |
| 需确认 | 未知组件版本、无法比较的手动版本、适用游戏版本声明、联动停用与部分成员缺失 |

预设外成员通常保持；所有联动例外逐项列出。对名称相同的启用／停用目录形成的路径互换，首版明确阻断并要求先改名，不扩展为任意路径重排器。

普通预设只改启停状态，不写 INI。已有活动独立配置关联保持，状态差异会显示为脏状态。独立配置预设继续走 ProfileService 的 INI／脏配置确认流程，按钮和预览必须说明其额外范围。

### 4.2 计划、执行与失败

`PresetApplyPlan` 包含游戏／根、预设摘要、直接／联动变化、未变／缺失／阻断、最终状态、依赖依据、执行顺序、预计移动数和短期 token。token 绑定已保存预设、库／互斥／依赖、相关目录身份及配置证据、已选择的冲突／排除决定和组件版本。

修改选择后重算；原生确认必须基于主进程保存的最新计划。进入写队列后、对话框结束后重新核对，发现外部编辑／改名、成员／版本／根变化即停止，不继续套用旧确认。

建议将可执行的启停组用 **受限 v2 `preset-switch` 提交**，保留目录移动前身份和元数据，以避免提供者失败后仍把依赖它的成员启用。复用现有账本与回退，不引入任意目录／文件写入接口，不借用 `profile-switch` 名称掩盖新用途。文件数量为零，目录仍固定在当前 Mod 根，最多 5,000 个移动；超过预算不能生成执行授权。

预先检查可阻断问题；用户明确排除的缺失成员保留在结果中。实际提交失败时按账本回退；回退不完整则保留现场并指向“备份与恢复”。逐项报告 applied / unchanged / skipped / rolled-back / failed / interrupted，回退项不计入 applied。不得先报整体成功再异步修正依赖。

普通预设无需复制整个 Mod 库：使用受限目录／元数据提交记录支持中断回退。成功后的长期恢复仍由已有预设或用户备份负责，不新建无限历史副本。

预览 token 在依赖确认完成、提交开始后才消费；用户取消不写文件。同步回归独立配置路径的未知版本确认重试，避免提前消费预览 token 导致用户接受依赖提示后无法继续。

旧 `applyPreset` 入口也通过相同解析与确认，不能绕过新规则；批量启停仍保持自己的 UI 与既有依赖确认，只复用最终状态计算。新的结果类型不塞入失败 Result.details，依赖错误仍是 DependencyPlan。

## 5. F12：预设清单与独立配置迁移

### 5.1 文件与隐私

默认导出 **`*.kmm-preset.json`**，只含明确选择的方案名称、游戏、成员显示信息、来源、声明版本、启停选择及可用指纹。独立配置用户可显式选 **`*.kmm-profile.zip`**：只打包清单和所选捕获 INI，不打包 Mod 内容、纹理、DLL 或游戏文件。

| 数据 | 导出规则 |
| --- | --- |
| 本地 Mod／预设／修订 UUID、原根与绝对路径 | 不当作可移植身份；以文件内部短 key 关联，不导出根和机器标识 |
| 网站身份 | 保存 provider、Mod/File ID 和 entryPath；sourceUrl 去掉用户信息、查询与片段；不带下载地址或登录凭据 |
| 名称、版本、启停 | 作为方案内容预览给用户；声明版本不证明实际内容或游戏效果 |
| 收藏、标签、手动备注、日志、兼容性标记 | 默认不导出，不覆盖目标库同类信息 |
| 依赖／互斥声明 | 如导出，使用成员短 key，作为可见来源提示；不自动改写目标 Mod 的全局要求或创建互斥组 |
| 捕获 INI | 需单独勾选，显示文件、大小、摘要和可查看原文；提示可能含私人参数／注释。不静默删改原字节后仍声称原摘要有效 |

JSON 格式建议采用固定 `format:'kmm-preset'`、`schemaVersion:1`、gameId、方案名、members 和可选 profile 描述；成员采用文件内唯一 key。示意：

```json
{
  "format": "kmm-preset",
  "schemaVersion": 1,
  "gameId": "zzz",
  "name": "常用组合",
  "members": [
    {"key": "m1", "name": "外观 A", "enabled": true,
     "source": {"provider": "gamebanana", "modId": 123, "fileId": 456, "entryPath": "Variant"},
     "declaredVersion": "1.0"}
  ]
}
```

导出前先展示数据范围和隐私预览，再原生保存／覆盖确认；唯一临时文件提交，拒绝数据目录及两游戏的 Mod／loader／游戏目录。取消／失败不截断原文件。

### 5.2 识别与映射

导入从原生文件选择开始，不读取清单里指向的外部路径，不自动访问 URL。固定选定游戏；跨游戏清单直接阻断，未知版本／格式保留原文件并拒绝，不猜新版字段语义。

匹配只产生**可审核建议**，用户完成映射后才创建方案：

1. 本次完整内容指纹唯一一致：可建议该本地 ID；声明版本不同时仍显示差异。
2. 相同 provider + Mod/File ID + entryPath：显示站点身份一致；多候选、内容有改动或当前摘要未知时要求明确选择。
3. 仅同 Mod ID、规范来源 URL／版本、名称／角色：作为弱提示，不自动选“最新文件”或第一条结果。
4. 多个相同本地副本、版本分支和未知来源都允许用户手动选择本游戏成员，显示依据与局限；缺失项保持可见，不伪造本地 UUID。

首版要求映射一对一。两个外部成员映射同一本地 Mod 时，要先排除或改选，不能悄悄合并相反启停选择或配置文件。目标库的全局互斥／依赖约束始终有效。

部分匹配时，用户可以明确创建“仅已匹配成员的启停预设”，或者保存待匹配清单草稿；全缺失时只保存草稿，不创建看似有效的空方案。未匹配成员与原清单保留在有归属的导入回执中，以便重新匹配，不塞入 Preset.members 当作跨库 ID。

保存前显示新方案、映射／排除／缺失、来源差异和局限。方案一律新建本地 ID；同名可改名或取消，首版不覆盖已有预设。文件选择后内容变化、根／库／候选变化或计划过期要求重新检查。

### 5.3 独立配置：可移植身份与安全发布

配置 ZIP 只允许 `manifest.json` 和 `blobs/<sha256>.ini`。清单最多 4 MiB、成员最多 5,000、捕获项最多 2,048、单 INI 4 MiB、总原始 INI 64 MiB；ZIP 输入最多 80 MiB，实际解包总计最多 68 MiB、最多 2,049 个文件，不沿用普通 Mod 包的 2 GiB 宽上限。重复／大小写碰撞条目、链接、越界、未知文件和摘要不符均拒绝。JSON 在解析前限制字节数，校验结构时拒绝重复对象 key，不接受解析器静默取最后一个值。

仓库已有 fflate 用于测试生成 ZIP；生产若复用，应将锁文件对应版本纳入运行时依赖，核对 worker／打包方式，并使用受控流式处理，不能依赖 devDependencies 在发行时仍存在。读包复用已有 ZIP 防护并添加上述专用白名单；不手写新的归档格式。

本地 contentRevision UUID 不能证明另一库内容相同。配置导出前核对捕获修订仍适用于源 Mod；已换包的不适用配置阻断导出，先让用户重新适配。

为允许同版 Mod 的运行时 INI 不同，定义独立 **`profile-compatible-v1` 投影指纹**：对已验证的文件树，逻辑上仅把明确捕获的 INI 换为其保存字节，再计算版本化树摘要；不写磁盘。导出端和目标端用相同捕获字节投影。非捕获文件、资源、路径／类型或其它 INI 有差异时仍不匹配，不冒称配置可直接迁移。

目标成员映射和投影摘要均满足后，才把捕获项重写为本地稳定 ID／当前内容修订、新 presetId 与新 revision；逐一验证 Mod 内相对 INI 路径和 blob 摘要。配置有不适用／缺失成员时，不能标为完整独立配置；用户可保留草稿，或明确只导入启停方案。

新增 `ProfileService.importCaptured` 一类专用入口，默认**只保存非活动修订**，不调用会捕获当前磁盘或设置活动关联的旧 capture 路径。全部文件准备完成后再原子发布预设引用；失败留下带归属的未发布暂存，不能留有效引用指向半份配置。创建配置、预设和导入回执的发布需要持久提交阶段记录；不能只靠单个 JSON 原子写宣称多文件原子完成。

导入后活动配置、INI 字节和 Mod 启停不变；用户点击应用时走已有脏配置／备份／依赖流程。原清单的依赖说明用于展示或后续明确编辑，本地 Mod.requirements 不被导入覆盖。

## 6. 对应接口与兼容迁移

以下是**拟新增／拟调整**，不是当前已存在的 80 项 API；实施时以实际拆分更新 contracts、IPCContracts、preload、main handler、文档和 AST 消费者清单。

| 拟调用 | 返回／关键约束 |
| --- | --- |
| `prepareModImport(game, source)` | source 仅为本地 folder/archive 类型触发原生选择，或 owned downloadTaskId；取消 null，成功 PreparationJob |
| `readPreparationJob(id)` / `cancelPreparationJob(id)` | 响应进度／取消；区分仅写自身缓存与真实提交 |
| `reviseModImport(game, jobId, selections)` | 只接受已知 entryId、是否导入、相对目标和重复决定；返回完整最新 ImportPlan／token |
| `applyModImport(game, token)` | 主进程原生确认后重新验证，返回有 ID 的提交任务与逐项最终结果 |
| `preparePresetApply(game, id, choices, excludedIds)` | 后台只读任务；结果含完整 PresetApplyPlan；排除决定必须显式保存到计划 |
| `commitPresetApply(game, token, dependencyConfirmation?)` | 完整确认／复核后受限提交；取消 null；AppliedPresetResult 独立类型 |
| `previewPresetExport(game, id, includeCapturedIni)` | 导出内容范围、脱敏来源、所选配置摘要和过期 token |
| `exportPresetManifest(game, token)` | 原生保存 JSON／配置 ZIP；取消 null；受保护目录拒绝 |
| `preparePresetManifestImport(game)` | 原生选择 JSON／配置 ZIP，校验和匹配任务；不立即创建方案 |
| `revisePresetManifestImport(game, jobId, mapping)` | 只接受清单成员 key、当前本地 Mod ID、显式排除及启停／配置导入选择 |
| `commitPresetManifestImport(game, token)` | 新建方案／非活动配置或保存待匹配草稿，返回映射回执和逐项问题，不自动应用 |

准备与执行结果需要具体区分 running、waiting-confirmation、complete、partial、canceled、interrupted、error；大目录／文件列表按需分页，不传整棵目录或所有 INI 原文。默认保留离屏选择，异步更新不能覆写正在编辑的名称／目录／映射草稿。

兼容路径必须逐一迁移：本地 importMods、下载 install-plan／retry-install／install-current、普通 applyPreset 和独立 profilePrepareApply／profileApply。旧接口复用新领域解析器；需要用户重新预检时明确返回，不保持未经确认的直接提交旁路。兼容消费者与弃用状态由 AST 清单如实登记，不制造虚假页面调用。
